# 术语表与源码查找手册

## 1. 架构术语

| 术语 | 在本工程中的含义 | 常见误解 |
|---|---|---|
| Composition Root | 创建具体实现并连接依赖的入口，主要位于最终 binary/启动代码 | 不是所有业务逻辑都应放在 `main` |
| Adapter | 把外部协议或平台 API 转成内部类型，如 ACP、MCP、HTTP、沙箱 | Adapter 不应拥有领域事实 |
| Port | 上层依赖的稳定 trait/协议边界 | 不等于网络端口 |
| Actor | 单个异步任务独占状态，通过 channel 接受命令 | `Arc<Mutex<T>>` 不自动等于 Actor |
| Event Loop | 顺序消费事件并修改状态的循环，TUI 的核心单写者 | 渲染函数不是 event loop |
| Fact Source | 冲突或恢复时最终采用的数据所有者 | UI 缓存和日志通常不是事实源 |
| Derived View | 从事实生成的展示或请求快照 | 修改 view 不会自动修改事实 |
| Wire DTO | 为 JSON/JSON-RPC/gRPC/磁盘格式设计的序列化类型 | 不应让供应商字段污染所有领域代码 |
| Capability | 工具/客户端声明自己能做什么 | 声明能力不代表已获授权 |
| Finalized Toolset | 本轮模型可见的 tool specs 与运行时 dispatcher 的一致快照 | 不能给模型旧 schema、运行新实现 |
| Side Effect | 文件、进程、网络、Git、终端等外部状态变化 | 日志也属于副作用，但风险不同 |
| Result Unknown | 操作可能已发生，但调用方没拿到可信回执 | 不能简单当成失败并重试 |

## 2. Rust 与异步术语

### 2.1 所有权与共享

| 形式 | 意义 | 阅读时的问题 |
|---|---|---|
| `T` | 当前作用域拥有值 | 值被 move 后谁继续拥有？ |
| `&T` | 共享借用 | 借用跨过 `.await` 吗？生命周期是否安全？ |
| `&mut T` | 独占可变借用 | 谁保证同一时刻只有一个修改者？ |
| `Arc<T>` | 跨线程共享所有权 | `T` 是否 `Send + Sync`？内部如何修改？ |
| `Rc<T>` | 单线程共享所有权 | 是否运行在 `LocalSet`？不能跨 worker 线程 |
| `Mutex<T>` | 独占锁保护状态 | 是否持锁跨慢 `.await`？ |
| `RwLock<T>` | 多读单写 | 读多写少是否真实？是否存在写饥饿？ |
| `ArcSwap<T>` | 原子替换共享快照 | 旧请求持有旧 snapshot 是否符合预期？ |

### 2.2 Future、Task 与 Stream

- Future：一次异步结果；
- Task：由 executor 推进的 Future；
- JoinHandle：观察 task 完成的句柄，不持有时要确认 task 是否仍会运行；
- Stream：多个异步 item；
- Sink：异步接收多个 item；
- `select!`：等待多个异步分支，需检查取消安全和分支优先级；
- `CancellationToken`：协作式取消信号，只有检查点才能生效；
- `LocalSet`：在一个线程内运行 `!Send` Future。

### 2.3 Channel

| 类型 | 典型用途 | 关闭语义 |
|---|---|---|
| `mpsc` | 多调用者向 Actor 发命令 | 全部 sender 丢失后 receiver 返回 `None` |
| `oneshot` | 一条请求对应一个结果 | sender/receiver 任一端丢失都可观察 |
| `broadcast` | 多订阅者接收事件 | 慢订阅者可能 lag，需处理缺失 |
| `watch` | 只关心最新配置/状态 | 中间版本可能被覆盖 |
| unbounded channel | 低成本、不阻塞生产者 | 若速率无上限会耗尽内存 |

## 3. 产品协议术语

### 3.1 ACP

Agent Client Protocol 连接客户端界面与 Agent。它提供 session、prompt、cancel、notification 和能力协商。ACP 是边界协议，不是 Agent 内部状态模型。

### 3.2 MCP

Model Context Protocol 用于发现和调用外部 server 提供的工具/资源。Grok 需要把 MCP 的 tool schema、transport、OAuth 和错误适配到内部 Tool runtime。

### 3.3 JSON-RPC

消息分为 request、response、notification。request id 用于匹配响应；notification 没有响应。stdio transport 上 stdout 必须只承载协议 frame，普通日志应走 stderr，否则会破坏 framing。

### 3.4 SSE

Server-Sent Events 是基于文本帧的流协议。一个网络 chunk 可以包含半个、一个或多个 SSE event，因此必须使用 framing parser，而不是直接对每个 chunk 做 JSON 反序列化。

### 3.5 PTY

Pseudo Terminal 让子进程以为自己连接到真实终端，影响颜色、行缓冲、交互和信号。PTY 测试比普通 pipe 更接近用户真实行为，但也引入 resize、raw mode、控制序列和平台差异。

## 4. 会话术语

| 术语 | 含义 |
|---|---|
| Session | 一段可持续多轮 Prompt 的 Agent 上下文 |
| Prompt | 一次用户提交及其多轮模型/工具循环 |
| Turn | 一次模型采样及其响应；一个 Prompt 可能有多个 Turn |
| Attempt | 对同一采样请求的某次网络尝试 |
| ConversationItem | 对话有序日志中的类型化项 |
| ToolCall | Assistant 请求执行工具的结构化项 |
| ToolResult | 对应 call id 的成功、失败、拒绝或取消结果 |
| Interjection | Prompt 运行期间插入的用户内容或控制事件 |
| Prompt Queue | 当前 Prompt 运行时等待处理的后续输入 |
| Compaction | 将旧上下文摘要化以释放 context window |
| Rewind | 把会话和可选文件状态恢复到较早 Prompt 边界 |

注意：Prompt 与 Turn 不是同义词。模型请求工具后，工具结果写回，再次采样，仍属于同一个用户 Prompt，但已经进入下一 Turn。

## 5. TUI 术语

| 术语 | 含义 |
|---|---|
| View/App State | event loop 拥有的 UI 状态 |
| Action | 输入或异步结果的纯语义描述 |
| Effect | 需要异步/外部执行的工作描述 |
| TaskResult | Effect 完成后返回 event loop 的结果 |
| Reducer | 根据 Action 修改 state 并产生 Effect |
| Render | 从 state 计算终端 frame，不应偷偷执行业务副作用 |
| Scrollback | 已提交到终端历史或应用内部历史的内容 |
| Overlay/Modal | 覆盖主界面的交互层，通常截获输入 |
| Raw Mode | 终端逐键输入模式，退出时必须恢复 |
| Alternate Screen | 不污染普通 shell scrollback 的全屏缓冲区 |
| Bracketed Paste | 终端标记粘贴边界，避免内容被当快捷键逐个处理 |

## 6. 工具与安全术语

### 6.1 ToolSpec、Tool 与 ToolDyn

- `ToolSpec`：给模型看的名字、描述和 JSON Schema；
- typed `Tool`：具体 Args/Output 的 Rust 实现；
- `ToolDyn`：把不同工具类型擦除为统一运行时接口；
- `ToolDispatch`：按名称找到工具并执行的边界；
- `ToolCallContext`：session/prompt/call、cwd、权限、通知和资源句柄。

### 6.2 Permission 与 Sandbox

- Permission：根据策略判断 Allow/Ask/Deny；
- Sandbox：操作系统层实际限制文件、进程和网络能力；
- Managed policy：组织或平台施加的高优先级约束；
- Project trust：项目内容是否可参与配置/扩展发现；
- Fail closed：无法安全判断时拒绝扩大权限。

## 7. Git 与 Workspace 术语

| 术语 | 含义 |
|---|---|
| Workspace root | 文件和命令默认受控的根目录 |
| Worktree | 同一 Git repository 的独立工作目录 |
| HEAD | 当前检出的提交引用 |
| Index | Git 暂存区 |
| Hunk | diff 中一段连续修改 |
| Attribution | 将文件/hunk 变化归因到某个 Prompt/工具 |
| Checkpoint | 在重要边界记录可恢复状态 |
| File Version | hash、mtime/inode 或 generation 等并发校验标识 |
| Atomic Replace | 临时文件写完后 rename 替换目标 |

## 8. 可靠性术语

| 术语 | 含义 |
|---|---|
| Idempotency | 同一业务请求重复执行不会产生额外效果 |
| Deduplication | 识别并丢弃重复消息/记录 |
| Retry | 对可恢复失败发起新 attempt |
| Backoff | 重试前等待，通常指数增长并加入 jitter |
| Deadline | 整体操作绝对/累计时间预算 |
| Timeout | 某个局部阶段允许的最长等待 |
| Circuit Breaker | 持续失败时临时拒绝调用，冷却后探测恢复 |
| Backpressure | 消费者跟不上生产者时限制生产速率 |
| Lease | 有过期时间的任务所有权 |
| Fencing/Epoch | 防止旧 owner 的迟到写覆盖新 owner |
| Durable | 进程崩溃后仍可恢复，具体强度取决于 flush/fsync |
| Indeterminate | 无法判断操作是否提交 |

## 9. 从界面行为反查源码

### 9.1 快捷键没按预期工作

```bash
rg -n "KeyCode::|KeyEvent|KeyModifiers" crates/codegen/xai-grok-pager/src
rg -n "shortcut|keybind|binding" crates/codegen/xai-grok-pager/src
```

跟踪顺序：terminal event → 当前 modal/focus → key mapping → Action → reducer → render。

### 9.2 Prompt 一直显示运行中

```bash
rg -n "SessionCommand::Prompt|PromptTurnResult" crates/codegen/xai-grok-shell/src
rg -n "Completed|Failed|Cancelled" crates/codegen/xai-grok-sampler/src crates/codegen/xai-grok-shell/src/session
```

检查 terminal sampling event 是否到达、oneshot sender 是否被丢弃、ACP response/notification 是否被旧 generation 过滤。

### 9.3 工具在模型列表中但调用失败

```bash
rg -n "ToolSpec|FinalizedToolset|ToolDispatch|ToolDyn" crates/common crates/codegen/xai-grok-tools
rg -n "serde.*rename|JsonSchema|schema" path/to/tool
```

比较模型看到的 schema、名称映射、实际 Args serde 和 dispatcher registry 是否同一版本。

### 9.4 文件写入后 UI 没有 diff

```bash
rg -n "hunk|attribution|file.*event|notify" crates/codegen/xai-grok-workspace crates/codegen/xai-hunk-tracker crates/codegen/xai-fsnotify
```

区分文件 syscall、Workspace event、hunk tracker、Session notification 和 TUI diff view 五个边界。

### 9.5 退出后终端乱码

```bash
rg -n "raw_mode|alternate|bracketed|mouse.*capture|restore" crates/codegen/xai-grok-pager crates/codegen/xai-ratatui-inline crates/codegen/xai-crash-handler
```

检查正常退出、错误返回、panic、signal 和子进程接管终端五条清理路径。

## 10. 从错误类别反查责任层

| 错误现象 | 首查层 | 不应先改 |
|---|---|---|
| CLI flag 冲突 | Pager CLI/Clap | Session Actor |
| 配置字段非法 | config/types/validation | TUI renderer |
| 401 循环 | auth + HTTP retry boundary | Tool implementation |
| SSE 断流 | sampler transport/parser | ChatState persistence |
| tool unknown | finalized registry/name mapping | Workspace FS |
| schema 参数错误 | ToolSpec/serde adapter | 模型流 parser |
| 权限误放行 | policy merge/decision | Ratatui modal 文案 |
| 文件冲突丢失 | Workspace version/locking | Chat transcript |
| child 遗留 | process manager/PTY cancellation | model backend |
| 历史恢复失败 | Chat persistence/schema upgrade | terminal writer |
| 迟到 UI 内容 | prompt/request generation filter | Markdown renderer |

## 11. 查找类型的固定命令

```bash
# 定义
rg -n "^(pub )?(struct|enum|trait) TypeName" crates

# impl
rg -n "impl(.*) TypeName|impl .* for TypeName" crates

# 构造
rg -n "TypeName \{" crates

# enum 消费点
rg -n "TypeName::" crates

# serde/wire 名称
rg -n "rename.*wireName|wireName" crates

# 测试
rg -n "TypeName|behavior phrase" crates/**/tests crates/**/src
```

Shell glob 在不同环境可能展开过多；必要时先限制到一个 crate。

## 12. 查找异步生命周期

```bash
rg -n "tokio::spawn|spawn_local|JoinHandle|JoinSet" path/to/crate/src
rg -n "CancellationToken|cancelled\(\)|select!" path/to/crate/src
rg -n "mpsc::|oneshot::|broadcast::|watch::" path/to/crate/src
rg -n "abort\(|shutdown|close\(|drop\(" path/to/crate/src
```

对每个 spawn 建表：

| 问题 | 答案 |
|---|---|
| 谁创建 task？ | |
| 谁持有 handle？ | |
| 正常停止条件？ | |
| 取消信号？ | |
| 是否 join？ | |
| panic 如何观察？ | |
| task 持有哪些资源？ | |

## 13. 查找持久化与兼容

```bash
rg -n "serde\(|schema_version|version|upgrade|legacy" path/to/crate/src
rg -n "flush|sync_all|rename|tempfile|transaction" path/to/crate/src
rg -n "append|ReplaceHistory|checkpoint|rewind" crates/codegen
```

需要特别区分：写入用户态 buffer、写入 OS page cache、`flush`、`sync_all`、事务 commit 和调用方收到 ack。

## 14. 查找安全边界

```bash
rg -n "Allow|Ask|Deny|permission|policy" crates/codegen
rg -n "sandbox|profile|seatbelt|seccomp|landlock" crates/codegen/xai-grok-sandbox
rg -n "canonicalize|symlink|normalize|workspace_root" crates/codegen/xai-grok-workspace crates/codegen/xai-file-utils
rg -n "redact|sanitize|secret|credential|token" crates/codegen crates/common
```

安全审查不要只找 `unsafe`。权限合并、路径规范化、日志泄密、命令参数和插件信任都属于安全边界。

## 15. 新手调试顺序

1. 用日志确认 request/session/prompt/call id。
2. 找到事实源，不从 UI 文案猜状态。
3. 找到状态的唯一写者和命令 enum。
4. 找到产生事件的 task 及其 cancellation token。
5. 沿 `Result` 和 `?` 找最终错误映射。
6. 查看同名测试，确认设计行为而非偶然实现。
7. 只运行最小 crate/测试过滤器。
8. 修复后增加失败路径测试，而不仅是成功路径。

## 16. 常见阅读错误

- 看到 `Arc` 就认为线程安全问题已经解决；
- 看到 `send().await` 就认为操作完成；
- 看到 HTTP 2xx 就认为业务提交；
- 看到 token 就把它写入规范历史；
- 看到 cancellation token 就认为所有子任务都会自动结束；
- 看到 sandbox crate 就认为每条命令都实际启用了沙箱；
- 看到文件锁模块就认为所有编辑工具都走同一锁；
- 看到 serde default 就认为任意版本都兼容；
- 看到测试文件多就跳过测试，错失最精确的边界说明；
- 先深挖 Mermaid/渲染算法，却还不知道 Prompt 如何完成。

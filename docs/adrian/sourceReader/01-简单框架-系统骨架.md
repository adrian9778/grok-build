## 1. Why：为什么要分层

一个二进制要同时服务：交互 TUI、CI headless、编辑器 ACP、后台 leader、以及若干「被拉起就干活然后退出」的子进程。若不分层，这些模式会互相污染——UI 细节渗进 Agent 逻辑，OS 细节焊死在采样里。

分层把「**依赖方向**」钉死：上层可调用下层，下层不知道上层存在。这样：

- Agent 逻辑不依赖 Ratatui（可 headless 跑）。**可核验**：`crates/codegen/xai-chat-state/Cargo.toml` 与 `crates/codegen/xai-grok-sampler/Cargo.toml` 中**都没有** `ratatui`、也没有 `xai-grok-pager` / `xai-grok-shell`。
- 采样不依赖具体文件系统（可换实现/可测试）。`xai-grok-sampler` 只依赖 `xai-grok-http` 与 `xai-grok-sampling-types` 这一层的类型。
- 工具不依赖 UI（可在 leader 进程里跑）。`crates/codegen/xai-grok-tools/Cargo.toml` 显示它依赖 `xai-tool-runtime` / `xai-tool-types` / `xai-tool-protocol` / `xai-grok-tools-api` / `xai-grok-workspace-types`，**不依赖** `xai-grok-pager`、`ratatui`。

> 组合根 `xai-grok-pager-bin` 只负责「用哪个实现、以什么模式启动」，**不实现业务循环**：`crates/codegen/xai-grok-pager-bin/src/main.rs · main(+0)`（快照 `main.rs:2035`）与 `async_main(+0)`（快照 `main.rs:2132`）通篇是「解析参数 → 分发到某个 `run_*`」，真正的 TUI 主循环在 `crates/codegen/xai-grok-pager/src/app/event_loop.rs · run(+0)`（快照 `event_loop.rs:1031`）。

依赖规则（谁不该承担什么）：

- 展示层（`xai-grok-pager`）**不得**直接 `std::fs`/`Command` 写文件——必须通过 ACP → `xai-grok-shell` → `xai-grok-workspace`。
- 领域层（`xai-chat-state` / `xai-grok-sampler`）**不依赖** Ratatui、不依赖具体 FS，只依赖端口 trait（如 chat-state 的持久化接口、sampler 的 HTTP 客户端抽象）。
- 端口层（`crates/common/xai-tool-runtime/src/tool.rs · trait Tool(+0)`，快照 `tool.rs:37`；以及 `trait ToolDyn(+285)`，快照 `tool.rs:322`）定义接口，适配器（`xai-grok-tools/src/implementations/` 下的 `codex` / `opencode` / `grok_build` / `lsp` / `search_tool` 等，以及 `xai-grok-mcp`）实现它。
- 方向可核验：`xai-grok-tools` 依赖 `xai-tool-runtime`；`crates/common/xai-tool-runtime/Cargo.toml` 显示它依赖 `xai-tool-types`、`xai-tool-protocol`、`xai-grok-tools-api`。**反向依赖不存在**（`xai-tool-runtime` 不依赖 `xai-grok-tools`）。

## 4. 物理拓扑：默认单进程，可选子进程

默认**单进程**：TUI 与 Agent 在同一个 `grok` 进程内——`crates/codegen/xai-grok-pager/src/acp/spawn.rs · spawn_grok_shell(+0)`（快照 `spawn.rs:268`）会判断走内嵌线程（`spawn_agent_thread_direct(+97)`，快照 `spawn.rs:365`）还是 leader 连接。入口是 `crates/codegen/xai-grok-pager-bin/src/main.rs · async_main(+391)`（快照 `main.rs:2523`）处的 `xai_grok_pager::app::run(args, bg_update_rx).await`。

| 拓扑 | 何时 | 进程划分 |
|---|---|---|
| 默认 TUI | 交互使用 | 1 进程：Pager + 内嵌 Agent + Sampler 同体 |
| headless `-p` / `--prompt-json` / `--prompt-file` | CI / 脚本 | 1 进程：`crates/codegen/xai-grok-pager/src/headless.rs · run_single_turn(+0)`（快照 `headless.rs:802`） |
| `grok agent`（stdio ACP） | 编辑器集成 | 1 进程：`xai-grok-shell/src/agent/app.rs · run_stdio_agent(+0)` |
| Leader | 多客户端复用同一 Agent | Leader 进程（`run_leader` / `run_leader_server`）+ 客户端进程（连 socket，`connect_or_spawn`） |
| Workspace daemon | 远程 / 共享仓库 | `xai-grok-workspace-daemon` 独立进程（`src/daemonize.rs · daemonize(+0)`，Unix 分支快照 `daemonize.rs:140`） |
| MCP 子进程 | 外部工具 | `xai-grok-mcp` 拉起 stdio / HTTP server |
| Mermaid / Voice | 渲染 / 采集 | 特殊子进程，**启动即 `exit`**，不进 runtime |
| PTY harness | 端到端测试 | `xai-grok-pager-pty-harness` / `ptyctl`，仅测试期 |

> `main()` 的**最前面几行**就完成「特殊子进程」判定：`crates/codegen/xai-grok-pager-bin/src/main.rs · main(+3)`（快照 `main.rs:2038`）调 `xai_grok_pager::app::mermaid_worker::maybe_run_render_subprocess()`，`main(+6)`（快照 `main.rs:2041`）调 `xai_grok_pager::voice::maybe_run_capture_subprocess()`；任一返回 `Some(code)` 就 `std::process::exit(code)`，**连 CLI 都不解析**（`PagerArgs::parse_cli()` 在其后）。

## 6. 信任边界：什么不可信

| 不可信输入 | 谁产生 | 防御在哪 |
|---|---|---|
| 模型输出（含 tool call 参数） | xAI API | `xai-grok-sampler` 校验 + 权限层二次确认（`crates/codegen/xai-grok-workspace/src/permission/manager/mod.rs · enum PermissionHandle`，快照 `:67`） |
| 仓库内容（文件 / 补丁） | 本地 FS | `xai-grok-workspace` 走 WorkspaceOps，不裸 `std::fs` |
| MCP 返回值 | 外部 server | `xai-grok-mcp` 边界校验 + 超时 / 熔断（`crates/common/xai-circuit-breaker`） |
| Hub 返回值 | Computer Hub | `xai-computer-hub-*` 协议校验 |
| 远端设置 / 公告 | grok.com | `xai-grok-announcements` 与 shell 的 remote-config 路径 |
| Hook 输出 | 用户配置的 hook 脚本 | `xai-grok-hooks` + `crates/codegen/xai-grok-sandbox/src/hook_write_deny.rs · ensure_namespace_lockdown(+0)`（快照 `:400`） |
| 多进程并发写 grok-home | 同机其它 grok 进程 | `xai-grok-file-lock`（有界非阻塞咨询锁；取锁前经 machine-local acquire slot；消费方为 `crates/codegen/xai-grok-shell/Cargo.toml:147`） |

> 核心原则：**Agent 从不直接 `std::fs` / `Command`**，所有宿主副作用收口到 `xai-grok-workspace`（`crates/codegen/xai-grok-workspace/src/workspace_ops.rs · enum WorkspaceOps`，快照 `:1507`）。否则无法代理、无法审计、无法沙箱。

## 7. 技术选型表

| 关注点 | 选型 | 位置 | 为什么 |
|---|---|---|---|
| 语言 / 版本 | Rust `1.94.0`，edition `2024` | `rust-toolchain.toml:11` / `Cargo.toml:114` | 手动 bump，一次一个点版本 |
| 异步运行时 | Tokio `1`（`full`） | `Cargo.toml:281` | 手动 `Builder::new_multi_thread` 以控制线程数与 `shutdown_timeout` |
| TUI | Ratatui `0.29`（+ `ratatui-core 0.1`） | `Cargo.toml:234` / `Cargo.toml:235` | 立即模式渲染；文本输入自研 `xai-ratatui-textarea` |
| HTTP | Reqwest `0.12` + rustls | `Cargo.toml:240`、`xai-grok-http` | SSE 流式采样 |

## 8. 重实现时先画出的边界

从零重建时，第一天**不要**复制 102 个 crate。先画并锁死以下边界（详见 `04`–`15` 各章「重实现」小节）：

1. 组合根只分发，不放逻辑（`07`）。
2. `Action`/`Effect` 事件循环是 UI 与领域解耦点（`08`）。
3. `SessionActor` 单写者，回合循环是核心（`09`）。
4. `Sampler` 只产 `SamplingEvent`，不碰 FS（`09`/`05`）。
5. `Tool` trait 统一内置 / MCP / Hub（`10`）。
6. `WorkspaceOps` 收口所有宿主副作用 + 权限双层（`11`）。
7. 跨进程写 grok-home 一律经 `xai-grok-file-lock`（当前由 `xai-grok-shell` 消费），不裸 `flock`（`11`/`13`）。
8. `ChatPersistence` JSONL 是崩溃恢复基础（`13`）。

**判定「边界画对了」的最小实验**：把 `xai-grok-pager` 换成一个只读 stdin / 写 stdout 的 headless 客户端，如果 Agent 侧一行都不用改就能跑通（这正是 `run_single_turn` 与 `run_stdio_agent` 存在的原因），说明 L1/L2 边界是干净的。

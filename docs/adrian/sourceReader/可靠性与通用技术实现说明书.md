# 可靠性与通用技术实现说明书

> **场景**：grok-build 是个长期运行、要连网络、要执行命令、要管理状态的终端 Agent。它必须在「模型可能胡来、网络可能断、进程可能崩、权限必须收紧」的前提下仍然可靠。本章把散落在 07–16 章的**可靠性模式**集中成一份说明书——每条模式给「它解决什么、落哪、怎么实现」。
>
> **阅读说明**：源码基准 `SOURCE_REV = d5a0335a47221e8c9519936cb693e9b6450227ec`。所有 `file:line` 对应当前工作区代码，均来自前述章节已核对结果。本章是横切参考章。

## 第一层 · 简单框架（系统骨架）

可靠性 = 八条可复用的工程模式，覆盖「并发 / 边界 / 失败 / 崩溃 / 安全」五个维度：

```
┌────────────────────────────────────────────────────────────────────┐
│  并发安全          单写者 Actor 模型（会话/工具解析/权限）            │
│  边界收紧          fail-closed（权限/沙箱/检索一致默认拒绝）          │
│  一致性            SamplingEvent::Completed 提交屏障 / ToolStream 不变量 │
│  网络容错          AuthRetryMiddleware 重试+stamp / Hub 重连重放        │
│  进程容错          crash-handler（跨平台信号 + 崩溃报告 + 终端恢复）    │
│  会话容错          active-sessions 崩溃恢复 / session_search 可重建    │
│  系统安全          OS 沙箱 Landlock/Seatbelt + 子进程 seccomp         │
│  可观测/自愈       遥测事件化 / 自更新静默 / 配置分层合并              │
└────────────────────────────────────────────────────────────────────┘
```

| 维度 | 模式 | 落点 |
|------|------|------|
| 并发 | 单写者 Actor | 09/10/11 章 |
| 边界 | fail-closed | 11/13 章 |
| 一致性 | 提交屏障 / 流不变量 | 09/10 章 |
| 网络 | 重试+stamp / 重连重放 | 10/12 章 |
| 崩溃 | crash-handler | 本节 4.5 |
| 会话 | 崩溃恢复 / 可重建索引 | 13 章 |

## 第二层 · 一个完整例子（全路径走读）

以「grok 在跑一个长任务时进程崩溃，用户重启后」为例：

```
① 崩溃瞬间：
   crash-handler 捕获信号 (SIGSEGV/SIGABRT...) 写崩溃报告
   handler.rs:write_crash_blob / format.rs:CrashBlob
   终端状态由 terminal.rs:restore_in_signal_handler 还原（不残留乱屏）
        │
② 下次启动早期：
   check_previous_crash(crash_dir)  lib.rs:122  → 发现上次崩溃报告
   install(config)  lib.rs:81  装好新会话的信号处理（必须在 check 之后，
   因 install 会 O_TRUNC last-crash.bin，lib.rs:12-15）
        │
③ 同时 active-sessions 扫描孤儿：
   collect_crashed  active-sessions/lib.rs:40  → 按 PID 找残留会话
        │
④ 用户恢复会话 → 加载 Summary（向后兼容，13 章）
   记忆系统召回 {workspace_hash}/MEMORY.md
        │
⑤ 重新跑任务时若调远程 Hub 工具：
   HubConnection 重连/重放状态机 (xai-computer-hub-sdk/src/connection.rs:14-25) 自动恢复会话绑定
        │
⑥ 若中途 401：AuthRetryMiddleware 刷新重试 (retry_middleware.rs:36)
   每条请求带 stamp（StampedBearerSuffix:21）保证幂等
```

这就是「崩溃不丢状态、恢复不重复副作用、网络断能续上」的可靠性闭环。

## 第三层 · 详细逐步说明（主链路拆解）

### 步骤 1 — 并发安全：单写者 Actor

所有可变状态都收敛到「一个处理命令的通道」，命令串行化执行：

- 会话：`SessionHandle`/`SessionCommand`/`SessionLiveState`（09 章 `spawn.rs:188`/`handle.rs:47`/`commands.rs:249`）。
- 工具解析：`CompoundResolver` 用 `Weak<CompoundResolver>` + `session_id` 绑定，会话销毁不拖死远程连接（10 章 `resolver.rs:215`/`inner.rs:56`）。
- 权限：`PermissionManager` 是 actor（`manager/mod.rs:1404`）。

### 步骤 2 — 边界收紧：fail-closed

- 权限：规则未命中 = Ask，绝不默认放行（11 章 `types.rs` `Decision:219`）。
- 沙箱：即便权限全过，进程级 Landlock/Seatbelt + 子进程 seccomp 仍生效（11 章 `sandbox/lib.rs:159`）。
- 检索：SQLite 损坏即隔离重建（13 章 `xai-grok-session-search/lib.rs:7-8`）。

### 步骤 3 — 一致性：提交屏障与流不变量

- `SamplingEvent::Completed`（`events.rs:52`）是唯一提交屏障，流式 `Progress` 不进提交（09 章）。
- `ToolStream` 形状严格为 `[Progress*, Terminal]`，`Terminal` 恰好一个（10 章 `tool.rs:120`）；缺 `Terminal` 由 `dispatch.rs:64` 的 `stream_no_terminal` 兜底。

### 步骤 4 — 网络容错

- `AuthRetryMiddleware::execute_with_stamp`（`retry_middleware.rs:27`）注入 bearer + stamp，遇 401 刷新重发；`StampedBearerSuffix`（`retry_middleware.rs:21`）保证幂等。
- `HubConnection`（`xai-computer-hub-sdk/src/connection.rs:14-25`）断线后：把 parked waiter 以 `NetworkError` 快速失败 → 指数退避+全抖动重连 → 重跑 `hello` → `ToolServer` 重放 `serve{session_id, tools}`。

### 步骤 5 — 进程容错（crash-handler）

`xai-crash-handler/src/lib.rs`：

- 跨平台：Unix 经 `sigaction(2)` 捕 SIGBUS/SIGSEGV/SIGABRT；Windows 经 `SetUnhandledExceptionFilter` 捕访问越界（lib.rs:1-8）。
- `panic = "abort"` 的发布构建中，SIGABRT 捕获让 Rust panic 中止也留下崩溃报告（lib.rs:3-5）。
- 顺序契约：`check_previous_crash(crash_dir)`（lib.rs:122）必须在 `install(config)`（lib.rs:81）之前——`install` 会以 `O_TRUNC` 打开 `last-crash.bin`（lib.rs:12-15）。
- `install_terminal_restore_only`（lib.rs:101）只恢复终端不装完整 handler。
- `CrashHandlerConfig`（lib.rs:46）/ `CrashReport`（lib.rs:56）是配置与报告结构；底层 `handler.rs:write_crash_blob` / `format.rs:CrashBlob` / `symbolicate.rs:ResolvedFrame` 负责写盘与符号化。

### 步骤 6 — 会话与索引容错

- `active-sessions`：`register`/`unregister` 成对，崩溃留孤儿，`collect_crashed_in`（lib.rs:66）按 PID 存活判定（13 章）。
- `session_search`：FTS5 库损坏即 quarantine + 重建空库；`bootstrap` 全量重建带 lease；`manager` upsert 去抖（13 章 `lib.rs:4-11`）。

### 步骤 7 — 安全与运维

- OS 沙箱：进程网络开放（连 LLM），子进程网络 seccomp 封禁（11 章 `sandbox/lib.rs:271`）。
- 遥测：所有关键节点发 `TelemetryEvent`，统一经 `TelemetryClient`（12 章 `client.rs:48`）。
- 自更新：后台检测/安装/重启，必要时 `restart_grok`（12 章 `auto_update.rs:891`）。
- 配置：合并分层（managed → config → requirements → MDM → env），默认安全（06 章）。

## 第四层 · 补全所有逻辑与技术要点

### 4.1 八条可靠性模式对照表

| # | 模式 | 解决的问题 | 关键符号 | 章 |
|---|------|-----------|---------|----|
| 1 | 单写者 Actor | 并发竞态 | `spawn.rs:188` / `resolver.rs:215` / `manager/mod.rs:1404` | 09/10/11 |
| 2 | fail-closed | 默认放行导致越权 | `types.rs:219` / `sandbox/lib.rs:159` | 11 |
| 3 | 提交屏障 | 流式结果误当稳定 | `events.rs:52` | 09 |
| 4 | 流不变量 | 工具流缺终态 | `tool.rs:120` / `dispatch.rs:64` | 10 |
| 5 | 重试+stamp | 401/网络瞬断 | `retry_middleware.rs:27,21` | 12 |
| 6 | 重连重放 | 远程 Hub 断线 | `xai-computer-hub-sdk/src/connection.rs:14-25` | 10 |
| 7 | crash-handler | 进程崩溃留痕/恢复终端 | `lib.rs:122,81,46,56` | 本节 |
| 8 | 崩溃恢复/可重建 | 会话孤儿/索引损坏 | `active-sessions/lib.rs:40` / `session_search lib.rs:1` | 13 |

### 4.2 crash-handler 的「顺序契约」为何重要

`check_previous_crash` 必须早于 `install`：因为 `install` 打开 `last-crash.bin` 时带 `O_TRUNC`，会清空上一次的崩溃报告（lib.rs:12-15）。若顺序反了，上次崩溃证据会被启动自身抹掉，崩溃检测永远为空。这是「先读旧证据、再装新 handler」的硬约束。

### 4.3 Hub 重连重放的「快失败」语义

`HubConnection` 断线时，**不**无限阻塞等待——它立即用 `NetworkError` 了结所有 parked waiter（xai-computer-hub-sdk/src/connection.rs:18-22），让上层（工具调用）快速失败并被上层重试逻辑捕获，而不是死锁在悬空 socket 上。重连后 `ToolServer` 按活跃会话重放 `serve{session_id, tools}`（xai-computer-hub-sdk/src/connection.rs:25），恢复服务端侧的会话绑定。

### 4.4 幂等 stamp 的必要性

`StampedBearerSuffix`（`retry_middleware.rs:21`）把幂等 stamp 拼到 bearer 后缀。当 401 触发刷新+重发时，服务端可凭 stamp 去重，避免「重试导致重复副作用」（如重复提交）。这与「无副作用只读」的工具语义互补：写类操作靠刷新重试，幂等靠 stamp。

### 4.5 终端恢复的边界

`install_terminal_restore_only`（`lib.rs:101`）表明 crash-handler 把「终端还原」与「完整崩溃捕获」解耦——某些嵌入场景只想保证退出不残留乱屏，不装信号 handler。设计上二者可独立启用。

### 4.6 设计不变量小结（可靠性级）

1. **并发收敛**：可变状态走单写者 Actor，命令串行化。
2. **默认收紧**：权限/沙箱/检索一律 fail-closed。
3. **提交明确**：`Completed` 才是稳定结果；工具流必以单 `Terminal` 收尾。
4. **网络自愈**：401 刷新重试 + stamp 幂等；Hub 断线快失败 + 重连重放。
5. **崩溃留痕**：cross-platform 信号捕获 + 崩溃报告 + 终端还原；`check` 先于 `install`。
6. **会话可救**：孤儿按 PID 找回；索引损坏即重建。
7. **安全兜底**：OS 沙箱进程级 + 子进程 seccomp。
8. **可观测自愈**：遥测事件化 + 静默自更新 + 配置分层。

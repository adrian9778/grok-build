# 13 · 持久化、记忆与会话恢复

> **场景**：grok 关掉后，三样东西要能跨进程/跨会话存活——(1) **记忆**：跨会话沉淀的知识（如「这个项目的构建命令是 X」）；(2) **会话**：一次对话的完整状态，能被「恢复」或「搜索」；(3) **崩溃恢复**：异常退出后，下次启动能找出孤儿会话。本章拆解这三块持久化逻辑。
>
> **阅读说明**：源码基准 `SOURCE_REV = d5a0335a47221e8c9519936cb693e9b6450227ec`。三个子系统分别在：`crates/codegen/xai-grok-memory`（跨会话记忆）、`crates/codegen/xai-grok-shell/src/session`（会话持久化）、`crates/codegen/xai-grok-active-sessions`（TUI 会话崩溃恢复）、`crates/codegen/xai-grok-session-search`（会话全文检索）。所有 `file:line` 对应当前工作区代码。

---

## 第一层 · 简单框架（系统骨架）

三块持久化，地址不同、生命周期不同：

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ① 跨会话记忆 (Memory)—— 长期知识，按工作区隔离                             │
│   xai-grok-memory  (~/.grok/memory/, blake3(cwd) 分桶)                     │
│   lib.rs:1-17  (布局) / :21 (开关) / :55 (embed_missing_chunks)            │
│   壳层 shim: xai-grok-shell/src/session/memory/mod.rs:1                    │
└──────────────────────────────────────────────────────────────────────────┘
                ┌─────────────────────────────────────────────────────────┐
                │ ② 会话持久化 (Session)—— 一次对话的完整状态                  │
                │   xai-grok-shell/src/session  (Summary / SessionInfo)     │
                │   Summary 含 git head + cwd 切换提醒 (head_fields_tests)  │
                └─────────────────────────────────────────────────────────┘
                ┌─────────────────────────────────────────────────────────┐
                │ ③ 崩溃恢复 (Active Sessions)—— 找孤儿会话                   │
                │   xai-grok-active-sessions  (~/.grok/active_sessions.json) │
                │   register:29 / collect_crashed:40 / unregister:53         │
                └─────────────────────────────────────────────────────────┘
                ┌─────────────────────────────────────────────────────────┐
                │ ④ 会话检索 (Search)—— 在本地会话里全文找                     │
                │   xai-grok-session-search  (SQLite FTS5, session_search)   │
                │   lib.rs:1-15  (分层: fts/recovery/db/doc/bootstrap/manager)│
                └─────────────────────────────────────────────────────────┘
```

| 子系统 | 入口 | 位置 | 一句话职责 |
|--------|------|------|-----------|
| 跨会话记忆 | `xai-grok-memory` | `xai-grok-memory/src/lib.rs:1` | Markdown 记忆层，按 blake3(cwd) 分桶 |
| 会话状态 | `Summary` / `SessionInfo` | `xai-grok-shell/src/session/*` | 单会话元数据 + 对话历史落地 |
| 崩溃恢复 | `collect_crashed` | `xai-grok-active-sessions/src/lib.rs:40` | 启动时扫孤儿 PID |
| 会话检索 | `xai-grok-session-search` | `xai-grok-session-search/src/lib.rs:1` | SQLite FTS5 全文索引 |

> 会话数据文件的**落盘路径**由配置系统决定：会话目录经 `encode_cwd_dirname`（blake3 编码）落到 `grok_home/sessions/<cwd_hash>/`，详情见 06 章「路径系统」。

## 第二层 · 一个完整例子（全路径走读）

以「用户上次会话崩了，今天重新打开 grok，想找回那个会话并让模型记得项目约定」为例：

```
① 启动 → 崩溃恢复扫描：
   collect_crashed()  active-sessions/lib.rs:40
   → collect_crashed_in(grok_home)  :66
   → 发现 active_sessions.json 里有个 PID 已死的孤儿会话
        │
② 壳层把它列进「可恢复会话」；用户点开 → 从磁盘加载该会话 Summary
   （含 head_commit / head_branch / pending_cwd_switch_reminder，
    见 persistence_head_fields_tests.rs 的反序列化向后兼容）
        │
③ 会话恢复后，模型要回答「这个项目怎么构建」：
   记忆系统先召回跨会话知识：
   xai-grok-memory 读 {workspace_hash}/MEMORY.md（项目级）+
   ~/.grok/memory/MEMORY.md（全局级）
        │
④ 若 MEMORY.md 里没有，模型这轮产出的「构建约定」会被写回记忆：
   embed_missing_chunks(...)  memory/lib.rs:55  为该段生成嵌入以便语义检索
        │
⑤ 用户想翻「上周那次讨论 OAuth 的会话」：
   xai-grok-session-search 在 session_search.sqlite (FTS5) 里 BM25 检索
   （分层: fts/recovery/db/doc/bootstrap/manager，lib.rs:4-11）
```

链路说明：**记忆是「长期、跨会话、按工作区」；会话是「单次、可恢复、可搜索」；崩溃恢复是「兜底，找孤儿」**。三者都落在 `~/.grok/` 下不同子目录，互不干扰。

## 第三层 · 详细逐步说明（主链路拆解）

### 步骤 1 — 跨会话记忆的布局

`xai-grok-memory/src/lib.rs:1-17` 给出数据布局：

```
~/.grok/memory/
  ├── MEMORY.md                      # 全局精选知识
  └── {workspace_hash}/              # 每工作区（blake3(cwd) 前 16 位）
      ├── MEMORY.md                  # 项目级精选知识
      └── sessions/
          └── YYYY-MM-DD-{slug}-{sid8}.md   # 会话日志
```

- 工作区分桶键 = `blake3(cwd)[:16]`（与 06 章路径系统的 blake3 编码同源）。
- 开关（`lib.rs:21`）：通过环境变量 `GROK_MEMORY`、`[memory] enabled` 配置、或远端设置开启；关闭时宿主不初始化该 crate。

### 步骤 2 — 壳层记忆 shim

`xai-grok-shell/src/session/memory/mod.rs:1-10` 说明：记忆「核心引擎」已搬到独立的 `xai-grok-memory` crate，此模块只是**把核心公共面 re-export 到历史路径 `crate::session::memory::*`**，让壳层里约 30 个反向依赖调用点无需改动。只有 `hooks`（依赖 `crate::sampling` 与 `session_compact` 的会话胶水）留在本地。

> 这是一次「抽取 crate」重构的痕迹——读代码时遇到 `crate::session::memory::X` 实际指向 `xai-grok-memory::X`。

### 步骤 3 — 会话状态结构

会话持久化在 `xai-grok-shell/src/session/`：

- `Summary`：单会话摘要，序列化带 git head 字段（`head_commit` / `head_branch`）与 `pending_cwd_switch_reminder`，且**向后兼容**——旧会话文件缺这些字段也能反序列化（`persistence_head_fields_tests.rs:17-24`）。
- `SessionInfo`（`unified_list/row.rs:144`）、`SessionMetaEnvelope`（`unified_list/envelope.rs:45`）：统一列表/信封结构。
- `prompt_queue.rs` / `prompt_parser.rs`：提示词队列与解析（含会话内 prompt 的持久化）。

### 步骤 4 — 崩溃恢复

`xai-grok-active-sessions/src/lib.rs:1-3`：把「打开的 TUI 会话」登记进 `~/.grok/active_sessions.json`，用于崩溃恢复。**正常退出会移除条目；崩溃会留下条目**；下次启动 `collect_crashed` 找出孤儿（PID 已死）。

- `ActiveSession`(`:15`)：一条会话记录。
- `register`(`:29`) / `register_in`(`:46`)：登记（启动时）。
- `try_unregister`(`:35`) / `unregister_in`(`:53`)：正常退出时移除。
- `collect_crashed`(`:40`) → `collect_crashed_in`(`:66`)：启动扫描孤儿。
- `list_in`(`:74`)：列出当前登记。

### 步骤 5 — 会话检索

`xai-grok-session-search/src/lib.rs:1-15`：对本地 grok 会话做全文检索，后端是**可重建的 SQLite FTS5 缓存** `<grok home>/sessions/session_search.sqlite`。自底向上分层：

- `fts`：持有 schema、BM25 查询、带 fence 的 `meta` 写入。
- `recovery`：把不可用库文件分类、隔离（quarantine）、重建空库；`db` 是「打开+重试」 plumbing。
- `doc`：把「会话 + 抽取文本」转成索引文档。
- `bootstrap`：跨进程、带租约（lease）保护的**全量重建索引**。
- `manager`：对每个会话的 upsert 做去抖（debounce），并应答查询。

关键契约（`lib.rs:13-15`）：该 crate **从不直接读会话存储**——调用方注入 `SessionSource` 与 `ContentExtractor`，`updates.jsonl` 线格式归存储所有，不在此重复。

## 第四层 · 补全所有逻辑与技术要点

### 4.1 记忆系统的启用与嵌入

- 启用三选一（`xai-grok-memory/src/lib.rs:21`）：`GROK_MEMORY` 环境变量、`[memory] enabled` 配置、或远端设置。关闭则不初始化。
- `embed_missing_chunks`(`lib.rs:55`)：为记忆片段补全向量嵌入，支撑语义检索（而非仅关键字）。
- 两层 MEMORY.md（全局 + 项目）让「个人通识」与「项目约定」分离，避免互相污染；会话日志按日期+slug+会话 id 归档，便于回溯。

### 4.2 会话 Summary 的向后兼容

`persistence_head_fields_tests.rs` 暴露两条硬约束：

- `head_commit` / `head_branch` 为可选字段，旧会话缺省也能 `serde_json::from_str` 成功（`:17-24`）；序列化时 `None` 字段会被跳过（`:118`）。
- `pending_cwd_switch_reminder` 等新字段也走同样的可选策略（`:88-98`）。

含义：会话格式可以演进，旧会话文件不会因新增字段而加载失败——这是「会话持久化要长期可读」的底线。

### 4.3 崩溃恢复的 PID 判定

`collect_crashed_in`(`xai-grok-active-sessions/src/lib.rs:66`) 的核心是「按 PID 存活判定孤儿」：登记的会话若其进程 PID 不再存活，即判定为崩溃残留，纳入恢复列表（`collect_crashed_partitions_by_pid_liveness` 测试见 `:230`）。`register`/`unregister` 成对出现，异常退出时的缺失 unregister 正是被捕获的信号。

### 4.4 会话检索的健壮性设计

`xai-grok-session-search` 的几个工程要点：

- **可重建**：`session_search.sqlite` 损坏时 `recovery` 隔离旧文件并重建空库，绝不死锁（`lib.rs:7-8`）。
- **跨进程安全**：`bootstrap` 全量重建带 lease 保护，避免多 grok 实例并发重建冲突（`lib.rs:10`）。
- **去抖写入**：`manager` 对单会话多次 upsert 去抖，降低 SQLite 写压力（`lib.rs:11`）。
- **存储解耦**：经 `SessionSource` / `ContentExtractor` 注入，检索层不直接依赖会话存储实现（`lib.rs:13-15`）。

### 4.5 相关子模块（一览）

- `xai-grok-shell/src/agent/subagent/attempt_store` —— 子代理尝试（attempt）存储。
- `xai-grok-session-events` —— 会话事件。
- `xai-grok-foreign-sessions` / `xai-grok-shell-session-support` —— 外部/壳层会话支持。
- `xai-grok-workspace/src/session` / `xai-grok-shared/src/session` —— 工作区/共享层会话类型。

### 4.6 设计不变量小结（本章范围内）

1. **记忆分层**：全局 `MEMORY.md` + 项目 `{hash}/MEMORY.md` + `sessions/` 日志，按 blake3(cwd) 隔离。
2. **开关集中**：记忆由 `GROK_MEMORY`/`[memory] enabled`/远端三选一控制。
3. **会话可演进**：Summary 新字段可选，旧会话文件向后兼容可加载。
4. **崩溃可恢复**：正常退出 unregister，崩溃留条目，`collect_crashed` 按 PID 找孤儿。
5. **检索可重建**：SQLite FTS5 损坏即隔离重建；全量索引带 lease；upsert 去抖。
6. **存储解耦**：检索层经 `SessionSource`/`ContentExtractor` 注入，不直接读存储。

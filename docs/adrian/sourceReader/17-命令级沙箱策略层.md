# 17 · 命令级沙箱策略层

> **场景**：模型让 bash 工具跑 `cp build/app.tar ../release/`。这条命令**合法、不在权限规则黑名单里、也没越过 workspace 边界的静态校验**——但它要写的目录在工作区之外。第 11 篇讲的进程级沙箱对此一无所知：它在守护进程启动那一刻就套好了，一份粗 profile 覆盖整棵进程树，从此不再改变。本篇讲的是**另一套强制模型**：每次 spawn 前重新算一份「这条命令能写哪些根、能读什么、能不能联网、环境里能留哪些变量」的策略，把它渲染成操作系统包装，跑完之后把拒绝解码成一张**可以授权的卡片**，用户点头 → 落一条**带 TTL 的 grant** → 同一次调用**重放**一遍。
>
> **阅读说明**：源码基准 `HEAD = 42f4d7d3`（2026-10-27，`SOURCE_REV = 559751fd`；前次基准 `HEAD = 0e2bfffb` / `SOURCE_REV = 036a5d83`）。工具版本：Rust 1.94.0（`rust-toolchain.toml` `[toolchain].channel`）；workspace members 共 **107** 个。本篇所有偏移均在本基准下**回源码实测**得到（用 `python3 .progress/sr_tools.py offset <文件> <符号>` 复核），不是从别处抄的行位差。
>
> **索引记法**：`文件路径 符号：名字 偏移：+N`。**顶层符号**（自由函数 / 类型 / 常量 / trait）只写名字，其定义行即 `+0`，不标偏移；**成员**写成 `文件 · impl <Type> 函数：name 偏移：+N`，**`+0` = 该 `impl` / `trait` 的头行**。同一类型可能有多个 `impl` 块散在多个文件（Rust 的分形扩展），所以本文一律注明偏移是相对**哪个文件里的哪个 impl 头**。路径一律写全；只有 ASCII 图内因宽度限制用缩写，图下方给图注。
>
> **三条最容易写错的事实**（都在源码里有明文，本篇反复强调）：
> 1. **命令级沙箱 v1 只有 macOS Seatbelt 一个后端。** `crates/codegen/xai-grok-sandbox/src/command/backend.rs` · 符号：`BackendName` 是**单变体枚举**（只有 `Seatbelt`）；在 `src/command/` 目录里 `grep -rnE 'bwrap|landlock|Landlock'` **零命中**。Linux 上的强制**仍然只在第 11 篇的进程级那一层**。
>    第二个证据：`crates/codegen/xai-grok-sandbox/src/command/detect.rs` · `impl HostProbe` 函数：`preferred_backend` 在非 macOS 直接返回 `BackendChoice::Unavailable`，理由字符串写明「v1 has Seatbelt on macos only」。
> 2. **包装失败 = 这条命令不跑**，绝不静默裸跑；这与进程级 `SandboxManager::apply` 的「套不上就降级继续」**语义相反**，不能类推。
> 3. **这一层不认识 daemon。** `crates/codegen/xai-grok-sandbox/src/command/mod.rs` 的模块文档第一条不变量就是「守护进程本身永不被 confinement」；所有会话、卡片、传输语义都在 `crates/codegen/xai-grok-workspace/src/sandbox/` 与 `crates/codegen/xai-grok-workspace/src/permission/` 那一半（本篇第四层 4.5）。
>
> **与第 11 篇的分工**：第 11 篇 4.5.1 那张三层沙箱分界表**只划边界、不讲机制**；本篇就是它指过去的「机制」。读完本篇你应该能回答那张表留下的三个「不认识」：命令级不认识什么、宿主编排不认识什么、以及为什么 tools 侧只认识一个 trait。

## 第一层 · 简单框架（系统骨架）

### 1.1 为什么要有第二套强制模型

进程级沙箱（第 11 篇步骤 8 与 4.5）答不上来这三类问题：

- 「**这条**命令能不能写 `../release/`」——进程级的写允许集是启动时定死的，对所有命令一视同仁。
- 「**这条**命令能不能连 `api.github.com:443`」——进程级要么整个进程联网（agent 自己要调 LLM API，不能断），要么用 seccomp 把子进程一刀切断网，没有「按 host 逐条放行、放行还能过期」的位置。
- 「被拒之后怎么办」——进程级只能拒绝，产品上没有回路。

命令级层把「拒绝」变成一次**交互**：拒 → 解码成 `Violation` → 出一张卡 → 用户给一个带作用域与 TTL 的 allow → 落盘 → 重放。这是它存在的全部理由。

| 维度 | 进程级（第 11 篇 4.5） | 命令级（本篇） |
|---|---|---|
| 施加时机 | 守护进程启动一次（`apply()` → `install()`） | **每次 spawn 前重新构建**一份策略 |
| 粒度 | 整棵进程树共用一份粗 profile | 每条命令一份 `crates/codegen/xai-grok-sandbox/src/command/policy.rs` · 符号：`SandboxPolicy` |
| 网络 | 进程自身开放，子进程靠 seccomp 全断 | `符号：NetworkPolicy` 只有 `Off` 与 `Proxy{port}` 两个取值 + 回环代理逐 host/port 授权 |
| 写 | 启动时固定的 allow 集 | 写根 + 违规 → 提问 → grant → 重放 |
| 读 | — | `符号：ReadPolicy::Roots` 可选限读（含 git 元数据） |
| 平台 | Linux Landlock + bwrap bind-over + seccomp；macOS Seatbelt | **仅 macOS Seatbelt**（v1 单后端） |
| 失败语义 | 套不上 → 记一条事件、**降级继续** | 包装失败 → **这条命令不跑** |
| 谁在管 | 进程自己 | daemon 的 `crates/codegen/xai-grok-workspace/src/sandbox/mod.rs` · 符号：`WorkspaceSandbox`（每个 serve folder 一个实例） |

### 1.4 四条后端无关的不变量

`crates/codegen/xai-grok-sandbox/src/command/mod.rs` 的模块文档列了四条，它们是理解全篇的钥匙（原文措辞保留关键英文）：

1. **守护进程永不被 confinement**——「Nothing here calls the process-wide `nono` sandbox」。这一层只管被 spawn 的那条命令。
2. **包装失败 = 拒绝运行**，「never a silent unsandboxed launch」。
3. **保护地板由每个后端最后渲染，且永不可 grant**——「a grant inside one is rejected at load **and** at `with_grant`」。双重拒绝。
4. **过期在每次 build 时经注入的 `Clock` 求值，绝不在 load 时**——所以手改 grants 文件、另一个 daemon revoke 掉一条，本进程不用重启就能在下一次 build 收敛。

## 第二层 · 一个完整例子（全路径走读）

场景：文件夹的 sandbox 模式是 `enforce`，宿主是 macOS，权限规则层（第 11 篇步骤 4–7）**已经放过了**这条命令——`cp build/app.tar ../release/app.tar` 不在任何黑名单里，也不是「越界路径」那类静态可判的操作。真正拦住它的是内核。

```
      没有 transport？ 有 → 继续（没有就该 fail-closed 了）
      Ceiling::for_violation 不是 deny-only → 走 hub 发 `sandbox_violation` 卡
      卡上给出：被拦的是哪个路径、提议 grant 什么、可选作用域、TTL 档位 1h/1d/7d
        │
⑮  用户点「允许，本工作区，1 小时」
      decode_reply → SandboxAnswer::Allow{subject,scope,expires}
      （答案越界一律 **向下降级 clamp**，绝不向上）
      → record_grant（WS/sandbox/grants.rs · impl WorkspaceSandbox +97）
      → CMD/grant_store.rs · impl GrantStore 函数：add（+152）
         → 私有 edit → spawn_blocking → 函数：edit_rows_locked
         → 跨进程 flock（protected.rs · 函数：lock_in_turn 的排队票据队列）
         → 锁内重读 → 丢掉过期 → HeldDir::replace 原子写回
      → mark_replay（WS/sandbox/mod.rs +561）
        │
⑯  重放：AfterRun::Replay（result_path.rs）在同 call id 上再 dispatch 一次
      ReplayBudget 从 One 变 Spent（函数：spend）
      这一次 build 出来的策略里，write_roots 多了一条 `../release`（因为 grant 生效）
      cp 成功 → Finished::Ran
      若第二次还是违规 ⇒ 终局：replayed_under 有值 ⇒ 不再出卡，
      decide 里直接 Denied{after_replay}；绝没有第三次运行
```

**这条链上有三处「宁可什么都不跑」**：④ 的 session 目录不安全、⑥ 的控制 socket 没被地板盖住、⑧ 的 git 元数据没读动或硬链接别名可疑。它们和 ③ 的「包装失败」一起，构成这一层的默认取向：**跑不了 ≠ 裸跑**。

**另一条形态不同的链路（网络）**：命令执行**过程中**要连一个未授权 host，回环代理的 decider 会把这条连接**挂起（hold）**，在命令还活着时就发卡；用户答案变成一个 `HoldAnswer`，让连接继续或拒掉——`Replay::Resume{hold_id}` 是这条路径专用的，**跑完再解码永远产不出它**。详见第三层步骤 9。

## 第三层 · 详细逐步说明（主链路拆解）

### 步骤 1 — 接缝：tools 侧只认一个 trait

`crates/codegen/xai-grok-tools/src/sandbox_launch.rs` 全文件 223 行，只定义一件事：

- `Trait：SandboxLaunch`（该文件顶层 trait，头记作 `+0`）三个方法：`prepare`（`+3`）、`prepare_restoring`（`+17`）、`exited`（`+29`，默认空实现）。
- 入参是 `&mut tokio::process::Command` + `&OriginalArgv` + `&CallId`——**不吃 builder，只吃已经组装好的 argv/cwd**；返回值 `LaunchReceipt{ sandboxed, backend }`（同文件顶层结构）告诉调用方「这次真的被罩住了吗、被谁罩的」。
- 便利自由函数：`original_argv`（先记下原始 argv）、`prepare` / `prepare_restoring`（把 hook 为 `None` 的情况短路掉）、`child_env`、`wire_prepared`。
- **时序铁律**：`wire_prepared` 之后才装 stdio / kill_on_drop / detach，也才装进程级的 `child_net::restrict_child_network`。因为 `install_wrapper` 会把 `cmd` **整个换成另一条 Command**（见步骤 5），提前装的都会丢。
- 类型来源：`CallId`、`CallKind`、`BackendName`、`OriginalArgv` 都是从 `xai_grok_sandbox::command` **重导出**的，tools 侧不认识 `SandboxPolicy`、`Grant`、卡片语义。

实际 spawn 点（本次实测 `grep`，排除测试）：`crates/codegen/xai-grok-tools/src/computer/local/terminal.rs` 6 处 `sandbox_launch::prepare*` 调用（含一处 `prepare_restoring`）与一处 `sandbox_launch::exited`；同目录 `static_shell.rs` 与 `shell_state.rs` 各一处，用的是 `CallId::shell_init("static-shell")` / `CallId::shell_init("shell-state")`。这两类是 terminal backend **自己的** spawn（登录 shell、静态快照、rc 文件捕获），它们也被包装，但**不进调用表、不出卡**——这正是 `CallKind::ShellInit` 存在的理由。

### 步骤 2 — `prepare_inner`：模式、grants、策略的装配顺序

`crates/codegen/xai-grok-workspace/src/sandbox/launch.rs` · `impl WorkspaceSandbox` 函数：`prepare_inner`（偏移 `+85`）。它的顺序不是随意的，每一步都是某条安全性质：

| 序 | 动作 | 为什么在这个位置 |
|---|---|---|
| 1 | 取锁读调用表：`held_mode` / `floor_of` / `attempt_settling` / `session_of` | 锁只在这一段拿，后面全是无锁计算 |
| 2 | `mode = held.unwrap_or(self.mode().max(floor))` | 「读，不取」：重试要沿用第一次的模式；hub 在派发时 pin 的模式**比 folder 当前模式更硬**，folder 模式中途被改也不影响活着的调用 |
| 3 | `mode == Off` → `Ok(None)` | 唯一「完全不看策略」的出口 |
| 4 | `self.engaged.get()` 为空：`Observe` → `Ok(None)`；`Enforce` → `Err(NotEngaged)` + 记一次 `WrapFailed` | 没 engage 的 folder 无法保证地板，enforce 就拒跑 |
| 5 | `refuse_unless_session_dir_safe(mode)` | 地板拦不住「命令自己把 session 目录变成别人的」，所以 enforce 下一条都不跑 |
| 6 | `live_allows_now(session)` + 接上 `settling.once` | 「别的会话的『仅本次对话』行不是这个调用的」——session 键在这里生效 |
| 7 | `side = mode.is_wrapped().then(running_network_side)` | `Observe` 不接代理：`uses_proxy` 为真但 `is_wrapped` 为假，它只观察文件系统 |
| 8 | `build_policy(engaged, &grants, side)` | 见下面 |
| 9 | `extra_bases = bases_from_env(child_env(cmd, restored))`；`tag = CommandTag::for_call(call)` | 环境变量里指向目录的基（`PYTHONUSERBASE`、`XDG_DATA_HOME`）要进归属集；tag 是后面 SBPL `(with message …)` 与代理归属的来源 |
| 10 | `point_at_proxy(call, &tag, mode, side, &mut policy)` | 指针与凭据**同生同死** |
| 11 | `wrap_for_mode(mode, backend, cmd, original, &policy, &tag)` | 失败时：`backend.is_none() && mode == Enforce` → `EnforceUnavailable`（模型看到固定措辞），否则 `Wrap(error)` |
| 12 | 仅当 `call.kind() == CallKind::Tool`：`calls.remember(CallRecord{…})` | 满了就把命令**拒掉**（`Err(refused)`），并把刚铸的凭据一起丢掉 |
| 13 | `minted.keep()`；返回 `LaunchReceipt{ sandboxed, backend }` | `sandboxed = mode == Enforce && receipt.is_some()`——这个布尔后来是解码的「快拒」依据之一 |

`build_policy`（同文件 `+7`）把 9 个输入喂给 `SandboxPolicy::build`：`workspace_root`（必须是已 pin 的 `ServedRoot`）、`profile`、`grants`、`proxy`（从 `side.policy_endpoint()` 快照而来）、`tmp_dirs`、`control_socket_dir`、`grok_home`、`user_home`、`git_env`。返回前它做两件事，都值得单独记：

- `policy.env.set.clear()` ——**把 build 写好的代理指针清空**。文档注释的理由很硬：策略「不带指针出去」，唯一的写指针的人是 `point_at_proxy`，它要么和凭据一起写、要么完全不写。否则会出现「有指针没凭据」的授权洞。
- `assert_control_socket_protected(&policy, &self.control_socket_dir)`（同目录 `mod.rs` 顶层函数）——构建出来的地板**没盖住** daemon 自己的控制 socket 目录 ⇒ `ControlSocketUnprotected`，一条命令都不跑。「命令能碰到那个目录」= 「命令能给自己加权限」。

`resolve_profile`（同文件顶层）说明策略基线从哪来：它调进程级那套 `load_sandbox_config(workspace_root)` + `ProfileName::Workspace.resolve_profile(...)`。该函数定义上方的注释写明 **`GROK_SANDBOX_PROFILE` 在这一层被忽略：per-command 策略永远从 `workspace` 档位起**。解析失败时回落到一个手写的「bare workspace profile」字面量（读写根 = 工作区，不限网），并 warn。

### 步骤 3 — 策略求值：`SandboxPolicy` 与 `apply.rs`

`crates/codegen/xai-grok-sandbox/src/command/policy.rs` · 符号：`SandboxPolicy` 的七个字段（每个都带源码注释，注释比代码更能说明意图）：

```
read                 : ReadPolicy        // AllExcept{deny[]} 或 Roots{roots[], deny[]}
write_roots          : Vec<PathBuf>      // canonical 写根，protected 在其上挖洞
network              : NetworkPolicy     // 只有 Off | Proxy{port}
env                  : EnvPolicy         // excludes[] + set[]
protected            : Vec<Protected>    // 地板：永不可写、永不可 grant、每个后端最后渲染
build_cache_trees    : Vec<PathBuf>      //  curated 构建缓存树；一张 BuildCaches 卡才并进写根
unread_git_metadata  : Vec<GitMetadataUnread>  // 地板该读但没读动的 git 文件
```

`符号：NetworkPolicy` 定义上方的注释是**全层最要紧的一句话**：内核层网络策略永远只有 `Off` 与 `Proxy{port}`，**一条网络 grant（哪怕是「所有 host」）都不改内核策略**——它只是代理 decider 的一次判定；因此控制 socket 与运行时 socket「无论用户允许了什么」都不可达；连 DNS 解析也走代理（「the child never opens the resolver」）。

`符号：DenyEntry` 三变体（`Path` / `Glob{root,tail}` / `TreeExcept{tree,except}`）的 `impl DenyEntry` 函数：`covers`（偏移 `+3`）有一条**故意不对称**的规则：**glob 解析不出来时返回 `true`（覆盖一切）**。注释写明「分类绝不能读成允许、而渲染器拒绝渲染的那次读」。

`crates/codegen/xai-grok-sandbox/src/command/policy/apply.rs` 给 `SandboxPolicy` **追加**一个 `impl` 块（该块头记作 `+0`；这是 Rust 的分形扩展，impl 可以离开类型定义所在文件）：

| 成员 | 偏移 | 语义 |
|---|---|---|
| `with_grant` | `+18` | 把一条 grant 施加到策略上。**deny 行永不放宽策略**；`FsWriteRoot` 必须过校验且不与「family-denied / missing-holds」地板冲突，否则跳过 |
| `apply_grant` | `+28` | 原地版本 |
| `would_allow` | `+108` | 「策略会不会允许这个 blocked」——**只有 `FsWrite` / `FsRead` 会返回 true**；`Net` / `Capability` / `Unknown` 一律 false（「那是代理的事，不是策略的事」）。写：先查地板 `is_protected`、再查读地板 `is_read_floor`、最后 `allows_write`；读：先查所有读 deny，再按模式（`Roots` 用 `firmlink_spellings` 的拼写、**从不解析**）比较 |
| `is_read_floor` | `+138` | 是否有读 deny 覆盖该路径（秘密目录、grok home 的 auth 材料、别的 workspace 的 sessions、profile 的 deny）。「没有任何 grant 能去掉它，所以卡片提出来只会再失败一次 ⇒ 干脆不提」 |
| `is_protected` | `+182` | 地板判定。除 `covers` 外还覆盖 `git_dir_nodes`、`glob_prefix_nodes`、`missing_ancestor_nodes`（最后一个是重命名防御） |
| `is_ungrantable` | `+216` | grant 的 root 落在地板里 ⇒ 直接拒 |
| `allows_write` | `+275` | 私有内核 |

顶层还有 `函数：validated_grant_root` 与 `函数：symlink_free_spelling`：逐段走 grant 根，`index ≤ 1` 豁免，遇到 `NotFound` 停止遍历，其它错误一律 `UninspectableRoot`（**拒**）。

`build_at_pin` 的失败取向值得单独记：`PolicyError` 有一堆变体，但**单条 grant 施加失败只是 warn + 丢弃这一条**——「一行过期/非法的 grant 只让这次策略窄一点，不让所有命令失败」。这与地板类失败（直接拒跑）是两种量级。

### 步骤 4 — 唯一 spawn 门：`wrap_for_mode` 的三态

`crates/codegen/xai-grok-sandbox/src/command/backend.rs` · 函数：`wrap_for_mode`（顶层，定义行即 `+0`）是全层唯一决定「这条命令要不要被改写成带沙箱的另一条命令」的地方。三态：

| 模式 | 行为 | 返回 |
|---|---|---|
| `Off` | **完全不碰 `cmd`** | `Ok(None)` |
| `Observe` | 只 `env::apply_env_set_only`（只注入、不删除），照常执行、只记账 | `Ok(None)` |
| `Enforce` | 依次：无后端 → `Unavailable{reason:"no per-command sandbox backend on this host"}`；`policy.unread_git_metadata.first()` → `PolicyError::GitMetadataUnread`；`protected::hard_linked_protected_file(...)` → `HardLinkedProtected` / `HardLinkUnverified` / `ProtectedTreeUnchecked`；然后 `env::apply_env_policy` + `backend.wrap` | `Ok(Some(WrapReceipt))` |

它的文档注释点出两件事：**(a)** `Enforce` 是**环境过滤与这些前置拒绝唯一执行的地方**；**(b)** 前置拒绝发生在「`cmd` 被碰之前」。

同文件的其他关键顶层符号：`符号：BackendName`（**单变体 `Seatbelt`**）、`符号：BackendCapabilities{reduced}`（Seatbelt 的 `reduced = false`，注释：Seatbelt 能强制整个 v1 模型）、`符号：CallKind`（`Tool` / `ShellInit`）、`符号：CallId`（`kind` 是字段而不是前缀，但 `Display` 给出线上拼写 `<id>` / `shell-init:<label>`；`tool:` 前缀用于本身就叫 `shell-init:` 的工具 id，保证往返解析不会串）、`符号：CommandTag`（`impl CommandTag` 函数：`for_call` 偏移 `+4`，拼写 `grok-<call>`；它是 SBPL `(with message …)` 归属标签与代理 per-call 身份的来源）、`符号：OriginalArgv`、`符号：RenderedPolicy`、`符号：WrapReceipt`、`Trait：SandboxBackend`（其 `wrap` 的契约：不 spawn、确定性、强制拒绝在最后、无回退）。

### 步骤 5 — macOS 后端：渲染 + 换命令

`crates/codegen/xai-grok-sandbox/src/command/backend/seatbelt.rs`（整个文件在 `#[cfg(target_os = "macos")]` 下）：

- `impl SandboxBackend for SeatbeltBackend` 函数：`wrap`（偏移 `+11`）：先对**每个写根**做 `refuse_symlinked_root`，再 `render_enforce`，再 `install_wrapper`。
- 函数：`sandbox_exec_args`：argv 形态固定为 `[-p, <profile 文本>, -D NAME=VALUE …, --, <原程序>, <原参数…>]`。路径不进 profile 文本，而是走 `-D` 参数间接化。
- `crates/codegen/xai-grok-sandbox/src/command/backend/seatbelt.rs` · 函数：`install_wrapper`（顶层函数，不在 `impl` 块里）：**新建一条** `tokio::process::Command` 指向 `/usr/bin/sandbox-exec`（常量 `SANDBOX_EXEC` 在 `crates/codegen/xai-grok-sandbox/src/command/detect.rs`），逐条搬运 `cmd` 的 env（`Some` 设、`None` 删）与 cwd，`unsafe { pre_exec(mark_inherited_fds_cloexec) }`，最后 `*cmd = wrapper`。它的文档注释有三条硬约束：
  1. **不 detach**：`detach_command` 由 spawn 点在 `wrap` **之后**自己挂，因为「同一个 Command 上第二次 `setsid` 钩子会让 spawn 直接失败（会话领导者返回 `EPERM`）」。
  2. **它是唯一读 `EnvPolicy` 的地方**：环境已由 `wrap_for_mode` 过滤过，这里只是搬运。
  3. **spawn 点绝不许 `env_clear`**：`Command` 不会报告「清过」，包装器无法复现。
- 函数：`mark_inherited_fds_cloexec`：`pre_exec` 里把除 0/1/2 之外的继承 fd 全设 `FD_CLOEXEC`。先 `proc_pidinfo(PROC_PIDLISTFDS)` 写进 32 KiB 栈缓冲；失败退化成 `3..open_max_bound()` 的 `fcntl` 扫描，上界 `FD_SWEEP_CEILING = 1 << 20`。**注释里标了 SAFETY**：钩子只调 `getpid` / `proc_pidinfo` / `fcntl`，无分配、无锁，因此在多线程父进程的 fork–exec 窗口里安全（和第 11 篇 4.5 里 seccomp 过滤器必须预构造是同一条约束的两面）。
- 函数：`probe_sandbox_exec`：用 `TRIVIAL_PROFILE = "(version 1)(allow default)"` 跑一次 `/usr/bin/true`，超时 `PROBE_TIMEOUT = 5s`，失败分 `ProbeFailure::{Spawn, Exit, Timeout}`，stderr 截断后再呈现。这就是 `HostProbe` 在 macOS 上「探测一次」的实际动作。

**SBPL 渲染顺序 = 语义**（`crates/codegen/xai-grok-sandbox/src/command/backend/seatbelt_profile.rs` · 函数：`render_enforce`，本次实测它拼出来的次序）：

```
base.sbpl（内含 (version 1) 与 (deny default)、process-exec/fork/signal 允许）
  ↓ 再发一条 "deny default"（带本次命令 tag 的默认拒绝）
读：AllExcept → allow file-read*
    Roots     → platform_defaults.sbpl + 每个读根 (require-any (literal P) (subpath P))
                 ★ 拼写只用 firmlink_spellings，绝不 realpath
写：render_write_roots（require-not 挖洞 + 目录 unlink 拒绝）
网：render_network（只允许出站到 127.0.0.1:<proxy_port>）
偏好：preferences.sbpl（只在 AllExcept 读模式下并入）
────── 注释「grok: mandatory denies; nothing below may be re-opened by a grant」
强制拒绝：render_mandatory（地板、unix-socket 出站、每条 deny entry、
          Node 类条目、祖先 unlink 钉住；最后 deny file-read* 的收口）
  ↓ deny mach-lookup (xpc-service-name-prefix "")
  ↓ deny system-fcntl (fcntl-command 80 110)
```

三条不可省的细节：**(1)** SBPL 是 **last-match-wins**，所以「强制拒绝在最后」不是风格而是正确性——地板那几条必须压过前面所有 allow。**(2)** 最后那条 `system-fcntl` 的常量 `FCNTL_DENY` 注释写明原因：`F_MAKECOMPRESSED`(80) 与 `F_TRANSFEREXTENTS`(110) **能用只读 fd 改文件数据**——不拦就等于给了一个绕过写拒绝的洞。**(3)** 每条规则都带 `(with message "<tag>")`，路径一律经 `(param "NAME")` 间接化，防 SBPL 注入。

三个 `.sbpl` 文件头部 15–16 行是出处声明：**逐字抄自 OpenAI Codex CLI**（`codex-rs/sandboxing/src/seatbelt_base_policy.sbpl`，commit `93b44c3a`）。这一层不是自研基底策略。

### 步骤 6 — 拒绝 → `Violation`：解码只有一条粗糙通道

`crates/codegen/xai-grok-sandbox/src/command/violation.rs` · 函数：`decode`（顶层）。它的文档注释就是顺序说明书：

```
blocked_target（私有，快拒 + 粗解码）
   不在沙箱里跑过 / 退出码 0 / 126 / 127 → 不是沙箱干的，None
   coarse::decode_coarse(stderr, cwd, policy) → Option<Blocked>
would_allow(blocked) || is_os_denial(blocked, policy) → None（策略本来就允许 = 是 OS 在拒，不是沙箱）
propose::propose(blocked, policy, bounds) → (subject, disposition)
归属检查：可 grant 且 subject 不是 BuildCaches 且是 Fs*，而 OwnTargets 不覆盖该路径
          → subject = None，disposition = Informational{Unattributed}
Violation{ blocked, proposed, disposition, partial_output, replay: Rerun, exit_code, stderr_snippet(≤512B) }
```

`函数：is_os_denial` 的判断很讲究：`FsWrite` 的「最近存在祖先」如果本来就可写、且路径本身不在地板里 ⇒ 那是 mode 位、文件被占用这类 **OS 拒绝**，不该出沙箱卡；但如果路径本身受保护（`<ws>/.git/config`、第一次 `mkdir <ws>/.grok`），那就是地板在守线，**要告诉用户**。

`函数：refused_under_grant`（同一文件顶层）只在**重放之后**那一次运行被调用：它问的是反过来的问题——「策略（已经被 grant 放宽）允许的目标，还是被拒了」。源码注释强调：同一种形状在**第一次**运行时会被读成 OS 拒绝，只有 grant 之后的那次才读成「后端的局限」。

`crates/codegen/xai-grok-sandbox/src/command/violation/coarse.rs` · 函数：`decode_coarse` 是**全层唯一的解码通道 = stderr 关键词 + 退出码**。这决定了这一层的认识论：**每一个 target 都只是猜测，所以每一个都必须用户确认**。内部次序（实测）：setuid exec 拒绝 → 网络失败 → marker 行 + path token → 按程序名判能力 → 跳过 pycache 噪声 → `Unknown`。几个专门防误报的点：

- `REMOTE_MOUNT_ROOTS = ["net","Network","Volumes"]`：自动挂载根**从不 stat**（stat 会挂住）。
- `函数：is_never_sandbox`：`publickey`、`docker.sock` 这类不算沙箱拒绝。
- `函数：rename_sides`：`mv A B` 只有当 A 未受保护、B 受保护时才归到 B。
- `函数：extend_across_space` + `函数：as_path_token`：带空格/引号的路径（`Application Support`）靠 `is_dir` 试探着拼。
- `函数：stderr_tail`：按**字符边界**截断，不切出半个 UTF-8。

`crates/codegen/xai-grok-sandbox/src/command/violation/coarse/macos.rs`（49 行，`cfg(macos)`）把 Seatbelt 的统一日志行 `Sandbox: <proc>(<pid>) deny(1) <op> <target>` 解析成 marker：`file-write*` → `Marker::Write`，`file-read*` → `Read`，其它 `file-*` → `Denied`，`network-*` / `system-*` **返回 `None`**（交给网络与能力规则）。函数：`network_report` 处理两种形状：`deny(1) network-outbound remote:*:<port>`（**地址被掩码，只有端口精确**）与 `/private/var/run/mDNSResponder`（一次解析，没有端口）。这个文件的模块文档专门警告：**裸词 `sandbox` 绝不做 marker**——失败的 `cargo test` 会打印 target 目录、Chromium 打 `--no-sandbox` banner、Deno 打 `(deno sandbox)`，都是正常输出。

`符号：Disposition` 只有两态（`Grantable` / `Informational{reason}`），`符号：InformationalReason` 七个变体每一个都在解释「为什么这张卡提不出东西」：`ProtectedTarget`（在地板上）、`ProfileDeny`（profile 的 deny 条目，只能用户去改 `sandbox.toml`）、`Capability`（特权操作）、`UnproxiedNetwork`（代理根本没看见这条连接——**跑完再解码看到的所有网络拒绝都是这一类**）、`PolicyDenylist`（组织的拒绝名单拒的）、`Unattributed`（命令没指向它）、`DecodeFailed`（卡片带不动这个请求）。`符号：Violation` 的 `impl Violation` 函数：`produces_card`（偏移 `+14`）把最后一类钉死：**`Unknown` 永不出卡**，工具结果原样回给模型。

### 步骤 7 — 提议与归属：只提「最小、可撤销、不越界」的那个目标

`crates/codegen/xai-grok-sandbox/src/command/violation/propose.rs`：

`crates/codegen/xai-grok-sandbox/src/command/violation/attribute.rs` · 符号：`OwnTargets`：`trees` = `[cwd, served_root, env_bases]`，`named` = argv 里的路径 token（shell 命令**多扫一层**），上限 `符号：MAX_NAMED` = 256。它的模块文档给的是「为什么未归属要降级」：拒绝行里的路径可能是**别的进程**留下的、或者是攻击者塞进 stderr 的诱饵——给一个命令根本没碰的路径出卡，等于让用户替陌生人授权。唯一例外是 `BuildCaches`：「工具链不在 argv 里说出自己的缓存目录」（`cargo build` 写 `~/.cargo/registry/src`），那一族是 daemon 的表而不是从输出里读到的路径，所以它自带归属。

`函数：floor_with_unread`（顶层）是组装点：各表 + `TreeExcept(grok_home except workspace 或命令目录)` + sessions 的 `TreeExcept` + grant 文件与 `linked_grant_files` + 符号链接目标的重影。该模块文档**自己承认一处局限**：嵌套仓库的 `.git` 没被覆盖。

`crates/codegen/xai-grok-sandbox/src/command/git_config.rs` 的模块文档才是攻击面的叙述地：`core.hooksPath` 指到哪、worktree 指针文件指向哪、config include 链读到哪——**必须按 git 自己的读法去读（包括穿过符号链接）**，git 会读的每个文件都要以所有拼写进保护，每个链接另立成 `Node`。只有「git 会读 **且** 地板拦不住」才触发拒绝。上限常量六个：`GIT_METADATA_READ_LIMIT` = 1 MiB、`GIT_CONFIG_INCLUDE_DEPTH` = 10、`GIT_CONFIG_FILES_LIMIT` = 64、`GIT_DIRS_LIMIT` = 512、`SYMLINK_HOPS` = 40，加上 `WORKTREE_POINTER_FILES`（`commondir`/`gitdir`）与 `GIT_HOOK_NAMES`。读不动就落成 `符号：GitMetadataUnread` 的五个变体之一（`TooLarge` / `Unreadable` / `NotUtf8` / `IncludesUnfollowed` / `GitDirsUnlisted`）→ 进 `policy.unread_git_metadata` → **enforce 下一条命令都不跑**。`符号：GitConfigEnv` 的读法也照 git：`GIT_CONFIG_GLOBAL` 独占，否则 `XDG_CONFIG_HOME` + `~/.gitconfig`；相对路径直接算 `Unreadable`。

**include 词法与跟链的实测细节（收口轮回源码逐条读，此前只列职责）**——同一文件：

- 支持的 include 形态只有 `[include] path = …` 与 `[includeIf "cond"] path = …`。**条件一律不判定**：`includeif` 分支把 `conditional` 置 true（同 impl 内的 `visit`，其 `("includeif", Some(_), "path")` 臂），该文件照样跟读，只是其中的值另记入 `conditional` 旁路保护，不与 effective 值混写。旧式点分头 `[includeif.gitdir:/x]` 因为 subsection 里含 `:/` 被词法器判成**坏行** ⇒ 整个文件 `Unreadable`（git 自己会拒这种行）。
- 路径解析规则（`fn include_path`）：裸 `~` 与 `~/x` 拼 `user_home`；`~user` ⇒ `Err("is under another user's home")`；空值 ⇒ `Err("is empty")`；绝对路径原样；**相对路径 = 相对"包含它的那个文件"所在目录**（`config.parent().join(value)`），不是相对 workspace。另有 `%(prefix)/` 前缀 ⇒ 直接算解析不了（注释写明 git 会展开成自己的安装前缀，这里不知道）。以上失败**都不静默**，一律落 `GitMetadataUnread::Unreadable` 并带上原因串。
- **不存在 ≠ 读不动**：`scan.read` 返回 `None` ⇒ 该文件跳过不再展开；但**在调用 `visit` 之前**已经 `scan.protect(&include, "")`，注释原文「Protected whether or not it exists yet, so no command can create it」——**先保护，再决定读不读**，所以"目标还不存在"绝不能免检。
- 词法器（`fn config_entries`）支持的形态：`#` 与 `;` 注释、key 可以紧跟在 header 同一行、`\` 续行、引号与 `\\ \" \n \t \b` 转义、带引号的 subsection、BOM 与 `\r\n` 归一。section 与 key 按 git 的折叠规则**小写**，带引号的 subsection **原样保留**、点分的 subsection 小写；裸 key（无 `=`）解析成 `value = None`。**遇到 git 会拒的一行就截停**，并把「该行之后什么都不读」作为 `Unreadable` 的原因上报（测试 `a_config_line_git_rejects_leaves_the_file_unread` 钉住）。
- **无 glob**：include 值不做通配展开（全文件 grep 无通配处理路径）。跟链界限是 `depth > GIT_CONFIG_INCLUDE_DEPTH`(10) 或 `files_read >= GIT_CONFIG_FILES_LIMIT`(64) ⇒ 记 `IncludesUnfollowed`（**记下来，不是静默跳过**）；自引用 config 也只会记**一条**。
- 上限语义的另一半：1 MiB 之内的文件即使行数超限也**尽力读出** `hooksPath`（测试 `a_config_is_read_lossily_up_to_the_limit_and_is_unread_past_it` 钉住「恰好 1 MiB ⇒ `TooLarge` 且此时不再保护 hooks」——即"超限就放弃保护"这个方向是**故意**的，读不出 hooksPath 就不再假装知道它）。

文件原语（同一文件，被权限层复用）：`符号：FileOwner`、`函数：open_nofollow`（`cfg(unix)` 用 `O_NOFOLLOW|O_NONBLOCK` + `fstat` 判定；非 unix 用 `FILE_FLAG_OPEN_REPARSE_POINT`）、`符号：HeldDir`（逐段 `openat` 走目录 + 有界读 + `open_lock` 用 `O_EXCL` 竞争 + `replace` 原子替换）、`函数：hard_linked_protected_file`（`cfg(unix)`；非 unix 版本同名直接返回 `None`）——一个受保护文件如果有「第二个可写名字」（硬链接），就拒绝整条命令；BFS 扫描上限 `HARD_LINK_SCAN_LIMIT` = 4096 且**从不跟随符号链接**；秘密目录与工具树受列举上限约束时，取向是「**只不检查、不拒绝**」（否则一个正常大目录会让沙箱整体失效）。

### 步骤 11 — 观察模式与路径恒等

`crates/codegen/xai-grok-sandbox/src/command/observe.rs`：`Observe` 的记账是**每 workspace、内存、内容无关**的计数——不阻塞、不发问、不落盘。`符号：WouldBlock{kind, target, verdict, count, last_at}` 按「卡片会提议的那个键」聚合，`符号：WouldVerdict` 三态 `Ask` / `DenyRow` / `PolicyDenylist` 是「如果现在切到 enforce 会怎样」。上限 `符号：OBSERVE_SUMMARY_MAX_ROWS` = 200，超了 `evict_oldest`。网络那几行**只能来自代理的 `AllowAndRecord`**，绝不是从 stderr 猜的。

聚合键与卡片共用同一个算法：`crates/codegen/xai-grok-sandbox/src/command/violation.rs` · 函数：`proposed_subject` 就是「这张卡片会提议什么」，所以观察计数和真发卡的提议天然是同一个粒度。

`crates/codegen/xai-grok-sandbox/src/command/canonical.rs`：`函数：canonical_path` = fold_dots + 最长前缀 realpath + `/private` firmlink + Unicode NFC。`符号：VolumeRule`（`Exact` / `Apfs`）按 cfg 选宿主（测试缝 `with_volume_rule`）；APFS 上比较键做别名折叠 + 小写 + NFC，`is_within` / `is_same_path` / `strip_within` / `dedup_paths` 全走同一个 `comparison_key`。`符号：ServedRoot` 的注释是五条编号不变量，浓缩成一句：**解析一次，拼写只是身份，每次 build 前重新校验，没重新 serve 之前一律拒绝**；`符号：RootMoved` 就是那条 fail-closed 路径。还有一个刻意不对称：地板与 deny 用 `函数：resolved_spellings`（**包含**已解析形态），而 roots 用 `函数：firmlink_spellings`（**从不解析**），理由写在注释里——「build 之后没有任何路径被换过」，所以一个后来被换成符号链接的读根不能因为解析到目标而被允许。`GLOB_MEMO_LIMIT` 生产 1024、测试 `1<<20`。

`crates/codegen/xai-grok-sandbox/src/command/env.rs`：`符号：EnvGlobs` 用 globset（ASCII 大小写不敏感，建表时一次性编译）。`函数：apply_env_policy` 的**顺序**就是它的语义：先从「继承环境」和「显式设置」里删掉排除项，**再**写 `policy.set`——这样代理指针不会被自家的 `*KEY*` 之类的排除规则吃掉。`函数：apply_env_set_only` 只设不删，服务 `Observe`。默认排除集是 `EnvPolicy::default_excludes()` 的九个 glob：`*KEY*`、`*SECRET*`、`*TOKEN*`、`*PASSWORD*`、`*CREDENTIAL*`、`*_PAT`、`LD_PRELOAD`、`LD_LIBRARY_PATH`、`DYLD_*`——注释的理由很直白：「否则子进程会继承 daemon 环境里的每一个密钥」。

### 4.1 关键数据结构全集

```text
SandboxPolicy —— 一次 spawn 的全部输入（serde，可跨 hub 传）
  read        : AllExcept{deny[]} | Roots{roots[], deny[]}
  write_roots : [canonical…]           ← protected 在其上挖洞
  network     : Off | Proxy{port}      ← 没有 "Open"

  protected   : [Protected…]           ← 永不可 grant

判决分三层，谁判什么：
  策略层  would_allow(blocked) -> bool   只有 FsWrite / FsRead 会判 true

  交互层  Disposition                    Grantable | Informational{7 种 reason}

  subject    = FsWriteRoot{root} | FsRead{root} | NetHost{host:HostPattern, port?} | BuildCaches
  scope      = Call | Session | Workspace{root} | Global     is_persisted = 后两个
  decision   = Allow | Deny                                  Deny 遮蔽 Allow
  expires    = Ttl{seconds} | At{unix} | Never               每次 build 经注入 Clock 求值

  via        = Option<Provenance{command ≤ 200 字符, tool_call_id}>

  "*" 全放；"*.suffix" 只匹配**真子域**（不含 suffix 本身）；
  IP 字面量按解析后的地址规范化比较（任何拼写是一个 host，且没有 "*.…" 能盖住它）；忽略尾点

Violation
  blocked      = FsWrite{path} | FsRead{path} | Net{host?, port?} | Capability{Ptrace|Mount|SetUid} | Unknown{stderr_snippet}
  proposed     = Option<GrantSubject>   受 MIN_PROPOSED_COMPONENTS / NEVER_PROPOSED / is_too_broad 约束
  disposition  ·  replay = Rerun | Resume{hold_id}  ·  exit_code  ·  partial_output  ·  stderr_snippet ≤ 512
  produces_card() == false  ⟺ blocked 是 Unknown

宿主侧回程
  Finished   = Ran(default) | Violation(FinishedViolation{violation, mode, backend, replayed_under}) | RefusedUnderGrant

  LaunchReceipt{ sandboxed: bool, backend: Option<BackendName> }
```

### 4.2 安全边界语义

**默认拒绝**

- SBPL 起手 `(deny default)`（基底文件里一条，渲染器又补一条带命令 tag 的）。
- `NetworkPolicy` 没有 `Open` 取值；host grant **永不放宽内核策略**。
- 环境默认排除密钥类变量。
- 保护地板在 **load 时与 `with_grant` 时双重拒绝**，永不出现在 grant 里。
- 代理 unix socket 与控制 socket 目录：`PolicyInputs.control_socket_dir` 是**必填**字段（缺了直接是 `PolicyError`），再加 `assert_control_socket_protected` 的防御性拒绝。
- `unread_git_metadata` 非空 ⇒ enforce 下一条都不跑（hooks 去向未知）。
- 缺后端 / 缺 transport / 解码失败 / pin 丢失（`PIN_LOST_TEXT`）/ 调用表满 ⇒ 一律 fail-closed。
- `DenyEntry::covers` 对解析不了的 glob 返回 true。
- `live_shared` 在任一发文件读不到时只交 deny 行。

**默认可用（opt-out 型）**

- workspace 根作为写根；`default_tmp_dirs`；`VERIFIED_BUILD_CACHES`（读时校验摘要 ⇒ 默认可写）。

**显式 opt-in（一张卡换一次）**

- `BUILD_CACHE_TREES`（未校验，「工具链不重新校验就解压/执行的东西」）——一个 workspace 一张 `BuildCaches` 卡；
- 每个网络 host/port（`NetHost` + `HostPattern`）；额外读根 `FsRead`；Observe 的记账。

**按模式与宿主分层**

- `符号：SandboxMode` 的变体顺序就是 `Off < Observe < Enforce`（`Ord` 派生，注释：「这就是『收紧』的意思」）。
- **命令层的分层轴是 `SandboxMode` × `detect_backend()` 是否返回 `None`**，不是宿主类型。特别注意：`crates/codegen/xai-grok-workspace/src/host_kind.rs` · 符号：`WorkspaceHostKind` **只有 `Sandbox` 与 `Daemon` 两个变体、没有 `Local`**，且它描述的是凭据/API 语义；在 `src/command/` 与 `sandbox/` 的强制路径里 grep 不到它的分支（只有测试引用）。**别把第 11 篇 hub_gate 的宿主档位当成命令级沙箱的分层依据。**
- 平台：macOS 有 Seatbelt 强制；其它平台 `detect_backend()` 返回 `None` ⇒ **命令层在这些平台上不做任何内核 confinement**，只贡献策略计算、观察记账与代理记账；强制仍落在进程级那一层。

**一条产品级取舍**（`crates/codegen/xai-grok-sandbox/src/command/detect.rs` · 函数：`detect_backend` 的定义注释原文）：`Enforce` 但宿主没有后端时——**开发者自己选的** enforce 保持 enforce 并拒绝每一条命令；**灰度开关（remote settings）选的** enforce 在这个宿主上作为 `Off` 运行。

落点在 `crates/codegen/xai-grok-config/src/sandbox_mode.rs` · `impl SandboxMode` 函数：`resolve_on_host`（偏移 `+40`）与 `impl ResolvedSandboxMode` 函数：`on_host`（偏移 `+13`）。

### 4.6 高手备忘：边界条件与坑

1. **`Observe` 不注入代理指针。** `is_wrapped()` 只对 `Enforce` 为真，而 `point_at_proxy` 第一道门就是它；但 `uses_proxy()` 对 `Observe` 也为真（`env::apply_env_set_only` 会把 `policy.set` 里已有的东西设进去）。所以「observe 下命令能看到代理变量」是假的——observe 只观察文件系统，网络记账另有来源（代理的 `AllowAndRecord`）。
   > 读测试名时会被绊一下：`backend_tests.rs` 里有个用例就叫 `observe_sets_the_proxy_pointers_and_removes_nothing`，断言 Observe 下 `HTTP_PROXY` **确实被设进了 cmd**。它不反驳本条——那个 fixture 手工塞了 `set: EnvPolicy::proxy_vars(3128)`，测的是 `wrap_for_mode` 的单元语义（生产不可达的组合：策略构建阶段 `env.set` 本来就是空的，`xai-grok-workspace` 侧的 `point_at_proxy` 还带一道 `debug_assert!(policy.env.set.is_empty(), "the policy build leaves no pointer")`）。
2. **grant 的施加失败不会让命令失败。** `build_at_pin` 对单条 grant 施加失败是 warn + drop；但**地板类**失败是整条命令拒跑。看到「命令没跑」和「授权没生效」要分两头查。
3. **重放只有一次。** `ReplayBudget::One` → `Spent`；第二次违规走 `replayed_under` 分支直接 `Denied{after_replay}`，不再出卡。任何「为什么用户都 allow 了还拒」的第二层原因都在这里，不在 grant store。
4. **`Unknown` 不出卡也不改工具结果。** 解码是**启发式**的（唯一通道是退出码 + stderr 关键词），所以它注定有 `Unknown`；`produces_card()` 把它挡在交互之外，只记 `unknown` 事件。指望「所有沙箱拒绝都有一张卡」是错的。
5. **路径解析的两种拼写策略是故意相反的**：地板与 deny 要包含已解析形态（防止「换个拼写就绕过」），roots 从不解析（防止「build 之后根被换成符号链接、于是读到了目标」）。改 `canonical.rs` 之前先读这两条注释。
6. **`hacks` 类绕过已经有三处显式收口**：`system-fcntl` 的 `F_MAKECOMPRESSED`/`F_TRANSFEREXTENTS`（只读 fd 改数据）、`mach-lookup` 的 `xpc-service-name-prefix ""`、以及 `nono` 版本 pin 注释里那条 `mv x y && cat y`（`is_applied()` 为 true 也不代表拒绝顺序对）。改 SBPL 顺序 = 改安全性质，不是改格式。
7. **卡片是串行的、有截止时间的。** `card_turn(session)` 让一个会话一次只问一张；`CARD_DEADLINE` 直接复用 `ToolServer::HOOK_REQUEST_BACKSTOP_TIMEOUT`。超时/失败一律**保持拒绝**，没有「等太久就放行」这条路径。
8. **`SandboxPath::Gated` 会取代事前弹窗**，这是产品语义上最大的一处「权限层和沙箱层重叠」。它有三个降级条件：不是 `ToolKind::Execute`、folder 不在 `enforce`、该 shell 工具的输出不是解码器读的那种（`ToolOutput::Pi` / MiniSweAgent 纯文本 / MCP 原样返回都算不读）；再加上一条「要求后台运行 ⇒ 降级为 `Shell`」。`函数：shell_output_is_decodable` 用的是**白名单命名空间**——新出现一种 shell 工具时它落在「没列出」那一侧，即**保留事前弹窗**（安全侧）。
9. **`hard_linked_protected_file` 在非 unix 上恒返回 `None`**（同名两份 `cfg` 实现）。所以「硬链接别名检查」这一层在 Windows 上不存在；而 v1 本来也没有 Windows 后端，两者叠起来意味着**非 unix 平台上命令级层只剩策略计算**。
10. **`WorkspaceHostKind` 与命令级分层无关。** 它在 `hub_gate` 那条 match 里只有 `Daemon` / `Sandbox` 两臂，`#[default]` 是 `Daemon`（未知宿主取保守值），但在 `src/command/` 与宿主强制路径里没有任何以它为轴的分支——把它当沙箱分层轴读会得出完全错误的结论。

### 4.7 设计不变量小结（本篇范围内）

1. **一次 spawn 一份策略**，每次重新构建；过期只在 build 时经注入 `Clock` 求值。
2. **包装失败 = 不跑**；进程级才是「降级继续」。两套失败语义不可互相类推。
3. **地板不可 grant**，load 与 `with_grant` 双重拒绝，且由每个后端**最后**渲染（SBPL last-match-wins）。
4. **网络只由代理判**：内核策略永远 `Off | Proxy{port}`，host grant 不放宽它，连解析都走代理。
5. **解码是启发式**：唯一通道是退出码 + stderr，所以每个 target 都必须用户确认，且 `Unknown` 不出卡。
6. **提议必是最小可撤销目标**：段数下限、禁提表、过宽/解析跑出去一律收窄，未归属一律降级 informational。
7. **授权只向下降级**：越界答案 clamp 并记录；deny 行遮蔽 allow；读不到文件就只交 deny。
   > 遮蔽这条的**测试覆盖是单向的**：4.4.1 里那两条用例都按「先 add allow、后 add deny」构造（`grant_store_tests.rs` 实测如此），反方向没有用例。因为 store 每次 `live()` 都从整表重算、不是按插入序生效，所以「顺序无关」大概率成立，但**目前没有测试钉它**——要改这块的话，先补一条反序用例再动代码。
8. **持久层与磁盘同向**：锁内重读、丢过期、原子替换，「内存跟随磁盘，绝不反向」。
9. **daemon 永不被 confinement**，且控制 socket 目录没进地板时整条命令拒跑。
10. **macOS 单后端**：其它平台强制仍在进程级那一层，命令级只贡献策略、观察与记账。

# 15 · 跨模块完整运行链与场景

> **场景**：前面 07–14 章把系统拆成入口、TUI、Agent、工具、Workspace、认证、持久化、构建八个切面。本章把它们**重新缝回一条主线**——给你三幕「端到端场景」，每一跳都标出它落在哪一章、哪个 crate、哪个 `file:line`。读完后，你应当能在脑中把任意一次用户操作映射到具体代码。
>
> **阅读说明**：源码基准 `SOURCE_REV = d5a0335a47221e8c9519936cb693e9b6450227ec`。本章是综合章，所有锚点均来自 07–14 章已核对的当前代码，不引入新符号（除少量跨章串联说明）。

## 第一层 · 简单框架（系统骨架）

把八章的主角排成一条「请求→响应」流水线：

```
用户键盘
   │  (Action)
   ▼
TUI 事件循环  ──[08]──  同步 dispatch(Action)->Vec<Effect>  (dispatch/router.rs:149)
   │  (Effect, spawn 进 JoinSet)
   ▼
会话 Actor    ──[09]──  spawn_session_actor (spawn.rs:188) / SessionHandle (handle.rs:47)
   │  handle_prompt -> run_turn_via_sampler (sampler_turn.rs:1142)
   ▼
采样循环      ──[09]──  SamplingEvent::Completed 为提交屏障 (events.rs:52)
   │  产出 tool_use
   ▼
工具派发      ──[10]──  ToolDispatch::call (dispatch.rs:32) / CompoundResolver (resolver.rs:215)
   │  调用具体工具前先过两关：
   ├─ 权限    ──[11]──  PermissionManager (manager/mod.rs:1404) + gate_preflight
   └─ 沙箱    ──[11]──  SandboxManager (sandbox/lib.rs:159)
   ▼
Workspace 操作 ──[11]──  WorkspaceClient (workspace-client/lib.rs:159) / git_*
   │
   ├─ 认证    ──[12]──  AuthCredentialProvider (auth_provider.rs:39) + AuthRetryMiddleware
   ├─ 遥测    ──[12]──  TelemetryClient.record (client.rs:48)
   └─ 持久化  ──[13]──  xai-grok-memory (lib.rs:1) / active_sessions (collect_crashed:40)
   ▼
结果回流 → 模型下一轮 → 最终答案渲染回 TUI
```

> 这条主线同时被 **[14] 构建系统**支撑（proto 生成让 ACP 线格式一致、`build.rs` 固化版本），并在 **后台**由 **[12] 自更新**保持二进制新鲜。

## 第三层 · 详细逐步说明（主链路拆解）

### 步骤 1 — TUI 是「同步决策 + 异步执行」的分层

- **同步层**（`dispatch::dispatch`，`dispatch/router.rs:149`）：纯函数 `Action -> Vec<Effect>`，无 IO、可单测。这是「主链路怎么走」的答案核心。
- **异步层**（`effects::execute`，`event_loop.rs:4496`）：把 `Effect` spawn 进 `JoinSet<TaskResult>`（`actions.rs:2333`），主循环用 `tokio::select!`（`event_loop.rs:2552`）同时等键盘、定时器、任务完成。

### 步骤 2 — 会话 Actor 是「单写者」

`spawn_session_actor`（`spawn.rs:188`）建出一个单写者 Actor：`SessionHandle`（`handle.rs:47`）对外、`SessionCommand`（`commands.rs:249`）入队、`SessionLiveState`（`handle.rs:23`）是内部可变状态。所有对会话的修改都经命令通道串行化，避免竞态。

### 步骤 3 — 采样循环的「提交屏障」

`run_turn_via_sampler`（`sampler_turn.rs:1142`）只把 `SamplingEvent::Completed`（`events.rs:52`）当作一轮稳定结果。流式 `Progress` 不进提交，工具结果不在 token 流里拼接——这保证了「一轮 = 一个可决断的快照」。

### 步骤 4 — 工具派发的「统一入口」

无论内置/MCP/Hub/技能，`ToolDispatch::call`（`dispatch.rs:32`）是唯一被 runtime 调用的接口；`CompoundResolver`（`resolver.rs:215`）把多路工具源聚合成统一路由。模型侧永远只看到 `tool_id + args(Value) -> ToolStream<TypedToolOutput>`。

### 步骤 5 — 权限/沙箱是「工具执行前的横切」

`bash` 等工具自身不实现授权——它们只是 `PermissionManager` 的调用方（`manager/mod.rs:1404`）；沙箱则在更底层由进程启动统一套上（`sandbox/lib.rs:159`），对工具透明。两层都过才真正执行（详见 11 章）。

### 步骤 6 — 认证/遥测/持久化是「旁路但贯穿」

- 认证：每次出网请求经 `AuthCredentialProvider` + `AuthRetryMiddleware`（12 章）。
- 遥测：每个关键节点发 `TelemetryEvent`（12 章 `client.rs:48`）。
- 持久化：会话 Summary、记忆、崩溃登记表各自落盘（13 章）。

### 4.2 「单写者 Actor」贯穿全系统

三处都用同一模式（见 09 章）：

- **会话**：`SessionHandle` / `SessionCommand` / `SessionLiveState`。
- **工具解析**：`CompoundResolver` 用 `Weak<CompoundResolver>` + `session_id` 绑定（`resolver.rs` / `inner.rs:56`）。
- **权限**：`PermissionManager` 是 actor（`spawn_permission_manager` `manager/mod.rs:1404`）。

共同好处：**把并发收敛到单点串行**，状态变更可预测、可测试。

### 4.3 「同步决策 / 异步执行」在 TUI

- 同步：`dispatch::dispatch` 是纯函数，输入 `Action` + `AppView`，输出 `Effect` 列表。
- 异步：`effects::execute` 把 `Effect` 派发到 `JoinSet`，主循环 `tokio::select!` 多路等待。

这是「UI 永远不卡、逻辑可单测」的不二法门（08 章）。

### 4.4 「fail-closed」在多处一致

- **权限**：规则未命中 = Ask，而非默认放行（11 章）。
- **沙箱**：即便权限全过，进程级 Landlock/Seatbeat + 子进程 seccomp 仍生效（11 章）。
- **检索**：SQLite 损坏即隔离重建，绝不死锁（13 章）。

设计哲学统一：**默认收紧，显式放行**。

### 4.5 设计不变量小结（全系统级）

1. **入口单一**：`xai-grok-pager-bin` 组合根，23 变体 `Command`（07 章）。
2. **UI 分层**：同步 `dispatch` + 异步 `effects` + `tokio::select!`（08 章）。
3. **会话单写者**：命令通道串行化状态（09 章）。
4. **提交屏障**：`SamplingEvent::Completed` 才是稳定结果（09 章）。
5. **工具统一入口**：`ToolDispatch::call` 收敛所有平面（10 章）。
6. **执行前横切**：权限 + 沙箱双层（11 章）。
7. **旁路贯穿**：认证 / 遥测 / 持久化（12、13 章）。
8. **构建支撑**：proto 单源生成 + `build.rs` 嵌版本（14 章）。

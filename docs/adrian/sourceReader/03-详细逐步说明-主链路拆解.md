## 1. Why：为什么要在走通后再拆解

`02` 让你「知道这条路走得通」；`03` 让你「知道每一步为什么这么写、出错会停在哪」。只有逐跳确认参数与返回，重实现时才不会把 `prompt_id` 当普通字符串、不会在跨进程时丢掉 call id、不会把增量 token 误当完成消息。

---

## 2. 拆解约定：每跳回答 6 件事

每一跳都按此模板记录（对应 `00` 的 9 问）：

- **调用者 → 被调**：函数与 `file:line`。
- **入参**：传了什么（类型/字段）。
- **返回**：返回什么、谁消费。
- **错误**：`Result` 的 `Err` 怎么处理、会不会变通知。
- **状态**：哪个 Actor 的状态变化了。
- **边界**：同步/异步？同进程还是跨 ACP channel？

## 3. 逐跳拆解（H1–H8）

### H1 Terminal → AppView：`Action::SendPrompt`

- **调用者→被调**：crossterm 事件循环把键盘输入交给我们自己的输入处理，最终构造 `Action::SendPrompt(text)`。
- **入参**：`text: String`（用户输入）。
- **返回**：`Action` 枚举值。
- **类型定义**：`crates/codegen/xai-grok-pager/src/app/actions.rs:40`（`pub enum Action`）。
- **边界**：同步，进程内。

### H2 AppView → `dispatch`：纯函数分发

- **调用者→被调**：`dispatch(action, &mut app)` — `crates/codegen/xai-grok-pager/src/app/dispatch/router.rs:149`。
- **入参**：`action: Action`、`app: &mut AppView`（UI 状态，可变但仅 UI 层）。
- **返回**：`Vec<Effect>`（本例含 `Effect::SendPrompt`）。
- **错误**：分发本身不失败（`Effect` 是「意图」，不是「结果」）。
- **状态**：可能更新 `AppView`（如把 prompt 放进 scrollback 草稿）。
- **边界**：**同步、纯函数、不 `.await`** —— 这是 UI 可单测的关键。
- **路由细节**：`Action::SendPrompt` → `dispatch_send_prompt`（`crates/codegen/xai-grok-pager/src/app/dispatch/prompt.rs:176`）；`Effect::SendPrompt` 在 `router.rs:1313` 产出。

### H3 `Effect::SendPrompt` → effects 任务 → ACP

- **调用者→被调**：effects 运行器消费 `Effect::SendPrompt`（`crates/codegen/xai-grok-pager/src/app/effects/mod.rs:1110`），构造 `acp::PromptRequest` 并 `acp_send(req, &tx)`（`effects/mod.rs:1141`）。
- **入参**：`agent_id`、`session_id`、`text`、`prompt_id`、`skill_token_ranges`。
- **返回**：`acp_send` 异步发送，结果经 `tx`（ACP 传输 channel）到对端。
- **错误**：发送失败 → 转成 ACP 错误通知或终端报错。
- **状态**：本侧「该 prompt 已发出、等待 session/update」。
- **边界**：**异步、跨 ACP channel**（同进程走内存 channel，跨进程走 stdio/socket）。
- **关键事实**：TUI 侧**没有** `SessionHandle::prompt` / `MvpAgent::prompt` 方法；prompt 一律经 ACP 传输。

### H4 ACP → `SessionCommand::Prompt` → `handle_prompt`

- **调用者→被调**：ACP 消息在 Session Actor 运行循环被匹配（`crates/codegen/xai-grok-shell/src/session/acp_session_impl/run_loop.rs:547`：`SessionCommand::Prompt { prompt_id, prompt_blocks, .. }`），分发到 `handle_prompt`（`crates/codegen/xai-grok-shell/src/session/acp_session_impl/turn.rs:249`）。
- **入参**：`prompt_id: String`、`prompt_blocks: Vec<ContentBlock>`、`session_id` 等。
- **返回**：回合结果（最终是 `PromptTurnResult` / `PromptCompletionKind`）。
- **错误**：`handle_prompt` 内任何 `?` 返回的错误，被翻译成 ACP 错误通知回 TUI。
- **状态**：`SessionLiveState` 从 `IdleResident` 变 `Working`（见 `crates/codegen/xai-grok-shell/src/session/handle.rs:23` 的枚举）。
- **边界**：**异步、Actor 单写者**（`SessionActor` 在 `acp_session.rs:645`）。

### H5 `handle_prompt` → `ChatStateHandle::build_request`

- **调用者→被调**：`handle_prompt` 调 `ChatStateHandle::build_request(...)`（`crates/codegen/xai-chat-state/src/handle.rs:361`）；拼装逻辑在 `crates/codegen/xai-chat-state/src/actor/request_builder.rs`。
- **入参**：当前 `prompt_blocks` + 已有对话历史（`ConversationItem` 序列）+ 系统提示/配置。
- **返回**：`ConversationRequest`（供 Sampler 消费）。
- **错误**：历史读取/序列化失败 → 回合错误。
- **状态**：ChatState 追加本条用户消息（对话事实的「唯一写入者」之一）。
- **边界**：跨 `await`（读持久化/压缩）。

### H6 `build_request` → `Sampler`：`run_turn_via_sampler`

- **调用者→被调**：`handle_prompt` 用请求驱动采样（`crates/codegen/xai-grok-shell/src/session/acp_session_impl/sampler_turn.rs:1142`：`run_turn_via_sampler(...)`）；内部经 `SamplerHandle`（`crates/codegen/xai-grok-sampler/src/handle.rs:19`）→ `SamplingClient`（`client.rs:357`）→ `stream_*`（`stream/responses.rs:202` 等）。
- **入参**：`ConversationRequest` + 采样参数（model、`reasoning_effort` 等来自 `PagerArgs`）。
- **返回**：**流**（`SamplingEvent` 序列），不是单次值。`SamplingEvent` 定义于 `crates/codegen/xai-grok-sampler/src/events.rs:52`。
- **错误**：HTTP/网络错误经 `classify_error` + 重试（见 `12`）；最终失败 → 回合错误通知。
- **状态**：`SamplerActor` 通过 `event_tx: mpsc::UnboundedSender<SamplingEvent>`（`actor/mod.rs:27`）把事件推给订阅方。
- **边界**：**异步、流式、可重试**（401 触发 OAuth 刷新等）。

### H7 `SamplingEvent` 回流 → ACP `session/update` → TUI

- **调用者→被调**：`run_turn_via_sampler` 把每个 `SamplingEvent` 翻译成 ACP `session/update`，发回 TUI。
- **入参**：`SamplingEvent::Delta`（增量文本）/ `SamplingEvent::Completed`（完成）等。
- **返回**：TUI 渲染增量。
- **错误**：传输中断 → 重连/报错（leader 重连属第二轮阅读）。
- **状态**：TUI `AppView` scrollback 追加文本。
- **边界**：跨 ACP channel（回程）。

### H8 `Completed` → `PromptTurnResult` → 屏幕定稿

- **调用者→被调**：`SamplingEvent::Completed` 被 `handle_prompt` 收尾为 `PromptTurnResult`/`PromptCompletionKind::Completed`，经 ACP 回到 TUI。
- **状态**：`SessionLiveState` 回到 `IdleResident`；本轮可恢复（JSONL 已落盘，见 `13`）。

## 4. 提交屏障：Completed 才是完成

> **不变量**：模型增量 token（`SamplingEvent::Delta`）**不是**规范完成消息；`SamplingEvent::Completed`（`PromptCompletionKind::Completed`）才是提交屏障。

重实现时绝对不能把「收到最后一个 token」当成「回答已定稿」——`Completed` 之前仍可能插入工具调用、压缩或插话。只有 `Completed` 承诺本轮终止。

## 5. 错误如何冒泡

```text
领域错误 (? 返回)
   │
   ▼
handle_prompt 捕获 → 翻译为 ACP 错误通知   [turn.rs:249 周边]
   │
   ▼
effects/ACP 传输 → TUI 渲染错误卡片        [effects/mod.rs:1110 周边]
   │
   ▼
AppView 显示；不崩溃进程
```

要点：

- 领域层用 `Result<T, E>` + `?` 向上传播，**不吞错误**。
- Session Actor 把 `Err` 翻译成 ACP 通知，而非直接 `panic`。
- TUI 只渲染通知，进程不退出（除非 `main` 顶层 `panic`/`shutdown_and_flush_telemetry`，见 `07`）。

## 6. 跨 await / channel 的状态变化

| 跳 | 是否跨 await | 是否跨 channel | 状态写者 |
|---|---|---|---|
| H1→H2 | 否 | 否 | `AppView`（UI） |
| H2→H3 | 是 | 是（ACP） | effects 任务 |
| H3→H4 | — | 是（ACP） | `SessionLiveState` |
| H4→H5 | 是 | 否（同 Actor） | ChatState |
| H5→H6 | 是 | 否（Sampler handle） | Sampler actor |
| H6→H7 | 是 | 是（ACP 回程） | `AppView` scrollback |
| H7→H8 | — | 是（ACP） | `SessionLiveState`→Idle |

> 设计含义：**UI 状态、会话状态、对话事实、文件事实由不同模块拥有**（`01` 不变量 1）。因此「跨 `await` 时状态会不会被改」的答案是：每个状态都有唯一单写者（Actor），不会竞态。
